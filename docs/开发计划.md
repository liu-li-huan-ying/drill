# 背单词 App 开发计划

> 定稿日期：2026-09-09
> 项目名：背呗（drill）
> 目标平台：Android（单机、离线优先、数据完全本地）

---

## 一、调研结论：付费软件的护城河在哪

| 产品 | 卖点 | 付费墙 | 我们的对策 |
|---|---|---|---|
| 墨墨背单词 | 抗遗忘调度 + 学习统计 | **单词上限**（背得越多越贵） | 本地 SQLite，无上限概念 |
| 不背单词 | 影视/纪录片原声例句 | 会员锁高清素材 | Tatoeba 开源句对 + 缺口 AI 补齐 |
| 百词斩 | 图片联想记忆 | 图库与增值项 | 不做（图片记忆对长期留存帮助有限） |
| 扇贝单词 | 词汇量测试筛熟词 + AI 助记 | 会员价最贵 | 筛熟词我们自己做，离线实现 |
| Anki | FSRS 算法最强 | 免费但 UI 简陋、要自己造牌组 | 用它的算法，不用它的壳 |

**核心判断：** 护城河 90% 不在技术。调度算法有 FSRS（开源，比 SM-2 少 20-30% 复习量达到同等留存率），词库有 ECDICT（MIT，150 万词条，带考纲标注与词频）。真正花钱的只有版权内容和体验打磨。

## 二、需求定稿（苏格拉底探究结果）

### 已确认的决策

1. **总库 + 标签模型**：维护一个 3 万词的全局词库（含 GRE 全覆盖），「词库」不是独立数据表，而是**作用在单词上的标签**。同一个词无论属于几个词库，全局只有一条复习记录，不会重复背。
2. **干掉的付费墙**：单词上限、自定义词库导入、例句与助记内容 —— 三个全部做掉。
3. **不做云同步**：改为本地进度备份文件（导出/导入），换设备时导入即可接续。
4. **纯离线、零 AI 运行时**：App 不联网、不调 LLM。AI 只出现在离线数据准备阶段。
5. **复习交互**：卡片翻转 + 四档评分（Again / Hard / Good / Easy），完整发挥 FSRS 精度。
6. **选词策略**：词汇量测试筛熟词，只背真正不认识的词。
7. **助记**：离线词根词缀规则拆解（来自 ECDICT 词根数据）+ 手写助记本地沉淀。

### 需求之间的冲突及解法

「例句免费」与「纯离线」存在张力：离线例句必须是一份打包进 App 的语料。

**解法**：Tatoeba 英中平行句对（约 22 万条，默认 CC BY）离线打包做主来源；覆盖率不足的低频词，导出缺口清单，由 AI 批量生成后回填（数据准备期完成，App 运行时仍是纯离线）。

## 三、技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Expo SDK 57（React Native 0.86 + React 19.2） | 当前最新稳定版，新架构强制开启 |
| 语言 | TypeScript strict | — |
| 路由 | Expo Router（文件路由） | 官方默认 |
| 本地库 | `expo-sqlite` + Drizzle ORM | 关系型数据、类型安全、live query |
| 调度算法 | `ts-fsrs` | FSRS 官方 TS 实现，纯 TS 无原生依赖 |
| UI 状态 | Zustand | 轻量 |
| 动画/手势 | react-native-reanimated + gesture-handler | 卡片翻转 |
| 发音 | `expo-speech` | 系统 TTS，零成本离线（MVP 妥协，真人发音包作增量） |
| 样式 | StyleSheet + 统一 theme 文件 | 不引 NativeWind，避免 SDK 57 的 Tailwind 构建风险 |
| 数据管线 | Python 脚本（离线跑一次，不进 App） | ECDICT / Tatoeba 预处理 |

> **第一步必做**：验证 `ts-fsrs` 在 Expo 环境能装能跑。这是整个方案的算法地基，先验再铺。

## 四、数据模型

```
words                    全局词条，只读
  id, word, lemma
  phonetic_uk, phonetic_us
  definition_zh, definition_en
  pos, collins, oxford3000
  bnc, frq                       词频排序，用于按频推进
  exam_tags                      逗号分隔：zk/gk/ky/cet4/cet6/toefl/ielts/gre
  exchange                       时态/复数变形 JSON
  root_affix                     词根词缀拆解结果

tags                     词库即标签
  id, name, kind(builtin|custom), color, sort

word_tags                多对多
  word_id, tag_id

cards                    每个 word 全局唯一一条
  word_id
  state                   new | learning | review | relearning
  due                     到期时间戳
  stability, difficulty, retrievability    FSRS 三变量
  reps, lapses, elapsed_days, scheduled_days
  last_review_at
  mastered                全局掌握态（词汇量测试产生，非 per-tag）；1=已掌握不再入队

review_logs              评分历史，供 FSRS 参数优化
  card_id, reviewed_at, rating(1-4), state, taken_ms
  prev_stability, prev_difficulty

sentences                例句
  id, en, zh, len, source

word_sentences           词 → 例句倒排索引
  word_id, sentence_id, rank

user_notes               手写助记
  word_id, mnemonic, note, updated_at

daily_stats              统计
  date, new_count, review_count, correct_count, elapsed_ms

settings                 键值对
  daily_new_limit, daily_review_limit, desired_retention, day_cutoff_hour
```

**关键设计点**

- `cards` 以 `word_id` 唯一索引 —— 这是「总库 + 标签」模型能成立的根本。
- 「词库」= `tags` 一行。导入自定义词表 = 给这批词打一个新 tag。
- 交叉筛选（如「考研 ∩ 未学」）由筛选器 UI 组合 tag 谓词实现，不物化成表。
- **复习候选池 = 拥有 tag 且 `mastered=0` 的词。** 词库只是往候选池加词，不持有复习状态（对抗式审查 C1 修正）。
- 一天的分界为**本地时间 04:00**（Anki 惯例，避免熬夜背词算到第二天）。
- **每日节奏默认新词 20 / 复习上限 200**，存于 `settings`，用户可在设置页随时自定义更改。

## 五、数据管线（离线跑一次）

### 5.1 主词典

1. 下载 ECDICT（`ecdict.csv`，约 200MB 完整版）。
2. 筛选 3 万词（确保 GRE 全覆盖）：
   - 取当代语料库词频 `frq` 前 25000；
   - 并集并入所有带考纲标签的词（保证考研/GRE 等低频考纲词不丢）；
   - 排除专有名词、缩写、含非字母字符的词条。
3. 输出 `dictionary.db`，目标体积 **< 30MB**。

### 5.2 例句索引

1. 下载 Tatoeba eng-cmn 句对（约 22 万条）。
2. 过滤：英文句长 4–20 词、中文翻译存在、无异常字符。
3. 用 ECDICT 的 `lemma.en.txt` 做词形还原，建 `word → sentence` 倒排索引。
4. 每个词保留最优 3 条（按句长适中、词频排序）。
5. 输出 `examples.db`，目标体积 **< 25MB**。
6. 导出**例句缺口清单**（无例句的词，预计 20-30%），交 AI 批量生成后回填，格式：

```json
{"word": "obfuscate", "pos": "v.", "zh": "使模糊不清",
 "examples": [{"en": "...", "zh": "..."}]}
```

### 5.3 产物

`assets/db/dictionary.db` 与 `assets/db/examples.db` 随 App 打包，首次启动拷贝到文档目录（需进度条，不能卡 UI）。

## 六、里程碑

> 每个阶段都有可验证的验收标准。上一阶段不达标，不进下一阶段。

### M0 · 环境与设计基线

- 初始化 Expo SDK 57 项目（TypeScript strict）
- 验证 `ts-fsrs` 在 Expo 下可安装、可调用、调度输出符合预期
- 建立 theme、目录结构、Drizzle schema 与迁移骨架
- 初始化 git 仓库，补 `MIT LICENSE` 与 README 骨架（开源从第一天起）

**验收**：`npx expo start` 能起，一个 demo 卡片能跑完一次 FSRS 评分并打印下一次 due 时间。

### M1 · 数据管线 v1（500 词样本）

- 跑通 ECDICT → SQLite 管线
- 产出 500 词样本包，用于快速端到端

**验收**：Python 脚本一键产出 `dictionary.db`，App 能读出 500 条词并显示音标与释义。

### M2 · 最小闭环（关键节点）

- 首次启动拷贝 db（带进度）
- 今日队列：到期复习 + 新词补充
- 卡片翻转 + 四档评分
- FSRS 调度写回，due 正确推进
- `expo-speech` 发音

**验收**：**真机（Android）上连续背 50 张卡**，退出重进后进度不丢，次日打开能看到正确的到期数量。

### M3 · 全量数据与例句

- 3 万词全量入库
- 例句索引入库，卡片详情页展示例句
- 导出例句缺口清单

**验收**：随机抽 100 个词，例句覆盖率 ≥ 70%；冷启动到可背词 < 3 秒。

### M4 · 词库与选词

- 标签系统：内置考纲标签 + 自定义标签
- 导入自定义词表（txt/csv，一行一词）→ 自动打 tag
- 全局搜索（支持词形还原模糊匹配）
- 词汇量测试：按启用词库/词频分层抽样（每层 50-100 词），自评认识的标记 `mastered=1`
- 设置页提供「重置已掌握词」入口，误判可清零重入候选池

**验收**：导入一份 3000 词的自定义词表，能立刻作为独立词库开始背；测试后新词队列显著缩短。

### M5 · 统计与备份

- 统计看板：连续打卡、每日新学/复习量、留存率、记忆持久度分布
- 备份导出为**单个 JSON**（含 cards、review_logs、notes、settings、schema 版本）
- 备份导入：合并到本地，冲突按 `last_review_at` 取新

**验收**：导出 → 清数据 → 导入，进度完整恢复，FSRS 参数一致。

### M6 · 助记与打磨

- 词根词缀自动拆解展示
- 手写助记编辑与检索
- （可选增量）真人发音包离线下载与缓存，替换系统 TTS（对抗式审查 C3）
- 边界处理：无网络、db 损坏、备份版本不匹配、空队列、时区切换

**验收**：断网飞行模式下全流程无报错；导入一份 v0 旧备份给出明确错误而非崩溃。

## 七、残留风险跟踪表

> 正式的对抗式审查见 `对抗式审查.md`。下表为审计后确认的残留风险（非阻塞，需跟踪）。

| 风险 | 影响 | 对策 |
|---|---|---|
| ECDICT 完整版 200MB，直接打包不可行 | 体积爆炸 | 管线预处理瘦身，目标 < 30MB；必要时用 mini 版补充 |
| Tatoeba 低频词覆盖不足 | 部分词无例句 | 缺口清单 + AI 生成回填（数据准备期） |
| APK 体积（db 55MB + bundle） | 安装慢 | 用 AAB 分发；db 首次启动拷贝而非 asset 直读 |
| 首次拷贝大文件卡 UI | 体验崩坏 | 后台任务 + 进度条 + 可中断续传 |
| FSRS 参数本地优化计算量大 | 主线程卡顿 | 前期用默认参数；积累 1000+ 复习后再优化，且放后台 |
| 日期切分错误（熬夜背词算错天） | 统计失真 | 固定本地 04:00 切分，写单测 |
| `ts-fsrs` 版本与 Anki 默认参数不一致 | 调度偏差 | 锁定版本，M0 阶段对比官方测试用例验证 |
| 备份 JSON 体积（3 万条记录） | 导出慢 | 仅导出有复习记录的卡；gzip 压缩 |

## 九、已确认决策（原待定项）

1. **项目名**：中文「背呗」，英文 `drill`（仓库名 `drill`）。
2. **总库规模**：3 万词，并确保 GRE 考纲词全覆盖（已并入 `exam_tags` 的 `gre` 标签）。
