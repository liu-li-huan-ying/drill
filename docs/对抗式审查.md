# 对抗式审查（Adversarial Review）

> 审查对象：`docs/开发计划.md` v1
> 审查日期：2026-09-09
> 方法：支持方完整陈述 → 挑刺方逐条攻击 → 循环 2 轮 → 裁决放行/修正
> 结论：**发现 1 处致命架构缺陷，已修正；1 处高风险、2 处中风险已缓解；方案可落地。**

---

## 第 1 轮

### 支持方陈述（核心决策）

1. 总库 2.5 万词全局唯一，词库 = 单词上的标签，复习实体 = 词（`cards` 以 `word_id` 唯一索引）。
2. 词汇量测试把「认识」的词标记 `suspended`，不再进入队列。
3. 复习交互用 FSRS 四档评分；例句打包 Tatoeba 离线；发音用 `expo-speech` 系统 TTS。
4. 不做云同步，本地 JSON 备份导出/导入。

### 挑刺方攻击

**C1 [致命] 标签模型与 `suspended` 语义冲突。**
`suspended` 是 `cards` 表的 per-word 字段，但词库是 per-tag 的。一旦词汇量测试把某词 `suspended`，它从**所有**词库消失。这破坏了「词库 = 标签筛选」的干净模型：
- 用户导入自建生词本 A 并把词 X 标记掌握，后来又建生词本 B 也想练 X，X 已被全局 suspended，B 里永远不会出现——但 B 的创建者意图是「我要练 X」。
- 更隐蔽：词汇量测试是一次性全局动作，它和「某个词库需要复习」在语义上不是同一层级的概念，却共用一个全局位。这是 per-word 状态与 per-tag 概念被错误合并的典型缺陷。

**C2 [高] 词汇量测试抽样 100 词对 2.5 万词太稀疏。**
100/25000 = 0.4% 覆盖率，筛熟词几乎等于没筛。用户以为「测过就干净了」，实际绝大部分熟词仍在队列里反复出现，与「只背不认识的词」目标严重背离。

**C3 [中] `expo-speech` 系统 TTS 英文发音质量存疑。**
中文系统下的英文 TTS 口音重、吞音，作为听感记忆素材体验硬伤。这是 MVP 的体验妥协，需明确标注，否则用户真机上第一声发音就会皱眉。

**C4 [中] Tatoeba 例句质量参差。**
部分句对是文学长句、机器翻译腔、或中文译法诡异；低频词（GRE 级）可能完全无例句，需 AI 回填但 AI 造句可能不地道。属数据准备期可缓解风险，但无自动校验机制。

### 第 1 轮裁决

**方案需修正。** C1 为致命缺陷，必须重定义复习状态语义。

---

## 第 2 轮（支持方修正后）

### 支持方修正

**C1 修正 —— 彻底分离两个概念：**
- `mastered`：单一位，表示「用户已掌握该词」。它由词汇量测试产生，是**全局事实**，不绑定任何词库。
- **复习候选池 = 所有「有 tag 且 `mastered=0`」的词。** 词库只是往候选池「加词」的机制，不是复习实体，也不持有复习状态。
- 这样词汇量测试标记 `mastered=1` 的词在所有词库都不出现——恰好是用户要的「认识就不背」，且语义自洽，不再有 per-word/per-tag 混乱。
- 误判防护：`mastered` 不是删除。提供「设置 → 重置已掌握词」入口，清零后词重新进入候选池；主动搜索复习也能唤醒。

**C2 修正 —— 分层抽样：**
词汇量测试按**启用词库 / 词频分层**，每层抽 50–100 词（总抽样约 300–600），覆盖率提升到可感知水平。

**C3 修正 —— 标注为 MVP 妥协 + 增量：**
MVP 用系统 TTS 跑通；`mastered`/发音包作为**可选增量**（离线下载真人发音包缓存，不破坏纯离线），列进 M6 之后的增强项。

**C4 接受为残留风险：** Tatoeba 例句在数据准备期人工抽样校验 + 缺口 AI 回填时加「避免生造、附可信语境」约束。

### 挑刺方再攻击（修正后方案）

- **Q1**：`mastered` 清零误判后，词重新入池会不会打乱 FSRS 已稳定的调度？
  → 支持方：清零 `mastered` 只是把它从「候选池排除」改为「参与」，并不重置其 `stability/difficulty`。若该词已有 FSRS 状态，沿用旧态继续调度；若是全新词，按 new 卡片入场。无冲突。
- **Q2**：`mastered` 作为全局位，是否意味着「在词库 A 掌握的词，在词库 B 也永远不出现」？
  → 支持方：正是此意图。用户认知是「词」层面而非「词在某词库」层面，全局掌握态符合直觉，且不引入 per-(word,tag) 状态爆炸。放行。

### 第 2 轮裁决

**无致命缺陷，可落地。** 但 C1 的修正必须反映到数据模型与里程碑，否则代码会按旧语义实现。

## 对开发计划 v1 的修改清单

| 项 | 原方案 | 修正后 |
|---|---|---|
| `cards.suspended` | per-word 全局跳过位 | 移除，改为 `cards.mastered`（全局掌握态） |
| 复习候选池定义 | 隐含「词库内的卡」 | 显式：有 tag 且 `mastered=0` 的词 |
| 词汇量测试 | 抽样 100 词 | 分层抽样（按词库/词频，每层 50-100） |
| 误判防护 | 无 | 设置页「重置已掌握词」入口 |
| 发音 | 系统 TTS（无标注） | 系统 TTS 跑通 + 标注为妥协 + 真人发音包作增量 |
| 审计位置 | 第七节「挑刺方清单」（单轮风险罗列） | 本文件为正式对抗式审计；计划第七节保留为「残留风险跟踪表」 |

**残留风险（不阻塞，需跟踪）**：Tatoeba 例句质量（C4）、APK 体积、首次拷贝卡 UI、FSRS 参数本地优化。已纳入计划第七节。
