## 0. 设计语言的由来

第一版原型做出来「没有辨识度」——靛蓝主色 + 16dp 圆角卡片 + 四色块评分按钮，本质是 Material 默认件的排列组合，换任何一家背单词 App 的 logo 都说得通。

问题在于**没有回答「这个 App 看起来应该像什么」**。市面上的共同形态是：无衬线字体、圆润卡片、插画或 emoji、高饱和渐变主色、游戏化打卡。单词在这些界面里只是**内容**，不是**主角**。

**「朱批」的回答是：让单词本身成为设计。**

三个记忆点：

1. **单词用衬线大字**（Iowan Old Style / Georgia / Noto Serif），UI 其余部分用无衬线。这是中英混排的经典做法，也是背单词 App 几乎没人做的。读起来像一页印刷品，而不是一张卡片。
2. **朱砂红 `#C0452F`** 作为唯一的强调色，只出现在极少数位置：主按钮、选中标记、进度条、「重来」档、词性标签。大面积留给纸白与墨黑。取自旧书上那支批注的笔。
3. **评分按钮顶部的横条长度 = 下次间隔**。重来 14dp、困难 26dp、良好 42dp、简单 66dp。不用读数字就能看出四个档位的量级差异——把抽象的「困难/良好」翻译成可见的长度。

## 2. 配色令牌

亮暗两套由**同一组令牌名**驱动，运行时跟随系统 `appearance`。

| 令牌 | 用途 | 亮（纸） | 暗（墨纸） |
|---|---|---|---|
| `--bg` | 页面底色 | `#F7F4ED` | `#1E1B18` |
| `--sf` | 卡片面 | `#FDFCFA` | `#272320` |
| `--pg` | 机身/分组底 | `#EFEBE3` | `#161412` |
| `--tx1` | 主文本（墨） | `#171512` | `#EAE3D7` |
| `--tx2` | 次要文本 | `#6E675E` | `#9A9083` |
| `--tx3` | 弱化文本 | `#A29A8E` | `#736B60` |
| `--bd` | hairline | `#E9E3D8` | `#332E28` |
| `--bd2` | 描边 | `#DAD3C5` | `#4A4339` |
| `--ac` | 朱砂 | `#A8382A` | `#E06859` |
| `--acsf` | 朱砂浅底 | `#F8EEEA` | `#33201B` |
| `--acon` | 朱砂上的字 | `#FFFFFF` | `#1E1B18` |

底色不是纯白而是**暖调纸白**（`#F7F4ED`，纸面 `#FDFCFA` 压在其上拉开层次）。**朱砂取印泥红 `#A8382A`（亮）而非亮橙红**——沉稳、有落笔的分量感（2026-09 定案，随 v3 原型）。

**深色是「墨纸」而不是「黑板」（2026-09-18 第三轮重做）**：深色不是纯黑，而是**墨在纸上**——底取深褐灰 `#1E1B18`（暖度 R−B = 6，是还能叫得出「褐」的下限），文字取米白 `#EAE3D7` 而非纯白（纯白压在暖底上是冷光，纸不是那样反光的）。三档底色同源递进：`pg #161412` < `bg #1E1B18` < `sf #272320`。

**朱砂在两套主题里必须是同一个色相**——这是本轮最要紧的一条：

| | 旧深色 | 亮色 | 新深色 |
|---|---|---|---|
| `ac` | `#D0684F` | `#A8382A` | `#E06859` |
| HSL 色相 | **11.6°**（橙侧） | 6.67° | **6.67°**（与亮色完全一致） |
| S / L | 0.585 / 0.588 | 0.60 / 0.412 | 0.685 / 0.614 |
| 压 `bg` 对比度 | 4.30:1 | 5.39:1 | 5.14:1 |

旧值偏了 5 度就落到「珊瑚橙」那一侧 —— 于是**深色模式里所有朱砂都不再像朱砂**，品牌锚点当场失效。修法：与亮色**同一色相、同一公式，只提明度**（暗色下朱砂还要当文字色用，低于 4.5:1 就不成立）。这条现在是断言，且是**实算色相**而不是比颜色名。

`acon`（朱砂上的字）在两套里都是「取低明度的那一端」：亮色是朱底纸白，暗色是朱底墨字 —— 白文印的语义在暗色里自然反转，不需要额外规则。

### 四档评分

| 档位 | 亮·底 / 字 | 暗·底 / 字 | 条长 |
|---|---|---|---|
| 重来 Again | `#F8EEEA` / `#A8382A` | `#33201B` / `#E06859` | 最短（对数刻度端点 14dp） |
| 困难 Hard | `#F2EFE7` / `#171512` | `#2A2723` / `#EAE3D7` | 按真实间隔插值 |
| 良好 Good | `#F4F3ED` / `#171512` | `#292A25` / `#EAE3D7` | 按真实间隔插值 |
| 简单 Easy | `#EBEEE5` / `#171512` | `#242A23` / `#EAE3D7` | 最长（端点 66dp） |

底 / 字即 `tokens.ts` 的 `b1..b4` / `b1t`；困难·良好·简单三档的字色取 `tx1`，条色取 `tx2`。只有「重来」用朱砂底朱砂字，其余靠底的冷暖微差 + 条长递进区分。不做四色高饱和色块。

**条长不是写死的四条**（2026-09-18 修正）：端点为 `RATING_BAR.min 14 / .max 66`，中间两档由这张卡**真实的四档下次间隔**在对数刻度上插值得到（`previewIntervals()`，见 `src/srs/fsrs.ts`）。原因：不同卡的四档间隔差着数量级——新卡实测是 `1 分钟 / 6 分钟 / 10 分钟 / 8 天`，成熟卡是 `10 分钟 / 2 天 / 3 天 / 4 天`。写死宽度会让「条长即间隔」变成假编码，而且卡片上印的间隔数字也会骗人。对数刻度是必需的：线性映射会把前两档挤成一样长。

> **令牌纪律（踩过坑）**：`body` 的文字色**必须走 `var(--tx1)`**，不得硬编码深色（如 `#1B1917`）。曾因 `body{color:#1B1917}` 硬编码，而 `body.ink` 只定义变量没覆盖它，导致**暗色模式下所有未显式设色的文字（刻度环数字、数据卡数值、完成屏标题、浮层标题、详情词面）继承成黑字、在墨黑底上全瞎**。修复：把 `body{color:#1B1917}` 改为 `body{color:var(--tx1)}` 并给 `.app` 兜底。同理——任何新文本元素要么显式 `var(--tx*)`，要么依赖继承的 `var(--tx1)`，绝不写死颜色。

## 3. 字体

两套字族分工明确：

- **衬线 `--serif`**：`Iowan Old Style, Palatino Linotype, Georgia, Times New Roman, Noto Serif, Source Serif 4, serif`
  用于：单词、页面标题、例句（斜体）、释义编号、统计数字
- **无衬线**：系统默认
  用于：释义中文、列表、按钮、标签、设置项
- **等宽**：`SF Mono, Consolas, monospace`
  用于：音标（配合 +0.8px 字距，词典感）

| 级别 | 字号 | 用途 |
|---|---|---|
| 58 sp 衬线 | 首页刻度环中心数字（`FONT.ring`） |
| 48 sp 衬线 | 复习卡正面单词（`FONT.cardWord`，臣服原则：单词是唯一主角） |
| 46 sp 衬线 | 统计页连续天数 hero（`FONT.hero`） |
| 36 sp 衬线 | 测试词 / 校准词（`FONT.test`） |
| 34 sp 衬线 | 详情页单词（`FONT.detailWord`） |
| 31 sp 衬线 | 统计页读数（`FONT.stat`，第三轮新增） |
| 27 sp 衬线 | 卡背面单词、统计数字（`FONT.wordSm`） |
| 25 sp 衬线 | 页面标题（`FONT.title`） |
| 16.5 sp 无衬线 | 中文释义（`FONT.def`） |
| 15 sp 无衬线 | 列表 / 按钮（`FONT.body`） |
| 14 sp 衬线斜体 | 英文例句（`FONT.quote`） |
| 13 sp 等宽 | 音标（`FONT.ipa`） |
| 12 sp 无衬线 | 数字的单位（`FONT.unit`，第三轮新增） |
| 10.5 sp 无衬线 | 小标签（`FONT.label`） |

命名即用途（`src/theme/tokens.ts` 的 `FONT`）：**同一个尺寸在不同屏上有不同使命，就应该是两个 token**。曾把复习卡的 48sp 与详情页的 34sp 都叫 `FONT.word`，改一处就误伤另一处；现已拆成 `cardWord` / `detailWord`。

### 字距（`TRACK`，第三轮新增）

**为什么要有这一组**：字距在前两轮是散落在代码里的 20 个裸值（`0.2 / 0.3 / 0.4 / 0.5 / 0.8 / 1.1 / 1.2 / 1.4 / 1.5 / 1.6 / 2 / 2.2 / 2.6 / 3 / −0.2 / −0.3 / −0.5 / −0.6 / −0.8 / −1 / −1.2`），而且**用错了地方**——「开始学习」这种按钮文案被拉到 1.5，大标题被拉到 3，字与字之间空到能塞进另一个字。

| 档位 | 值（px） | 用在哪 |
|---|---|---|
| `tight` | −0.6 | 大字号衬线单词 / hero 数字：**收紧**才有排印感 |
| `body` | 0.2 | 按钮文案 / 正文 / 列表 / tab 标签——**这是默认值** |
| `title` | 1 | 中文标题（25sp 级）：只留一点呼吸 |
| `label` | 2.2 | ≤11sp 中文小标签：章印式（`今 日 待 学`） |
| `caps` | 3 | ≤11sp 拉丁全大写小标签 |

判据只有一条：**宽字距是「小标签」的排版语汇，不是「大字」的**。报纸法则里 tracking 随字号**反向**变化——字越大字距越要收；反过来给大标题加拉宽，等于让每个字宣布自己是独立个体，读起来就是散的。

配套：字距必须走档位，**不许出现裸值**（已入断言）。原先靠「`'开 始 学 习'` 里手打 ASCII 空格」伪装宽字距的写法一并删除——那既不可调控，也会在换行时断在奇怪的位置。

### 字重（2026-09-18 修正，推翻旧结论）

> 旧结论写的是「中文层级不靠字重（中文无 light 档、bold 小字号糊），靠字号 + 字距 + 颜色」——**这是错的**。实测反馈：标签 / 按钮 / 小字用 Regular(400)，在中文屏显下**细弱无力、显廉价**；而靠拉宽字距假装层级，只会更散。**这两个毛病叠在一起，就是「实习生感」的来源。**

| 角色 | 字重 | 说明 |
|---|---|---|
| 正文长文（释义 / 例句 / 浮层说明） | **400** | 长文才用 Regular，加粗反而糊 |
| 标签 / 按钮 / 标题 / 数字 / tab 标签 | **600** | 10–24px 区间一律 600；PingFang SC Semibold 在小字号依然清晰，是「有力量」的直接来源 |
| 列表项标题 / 次要数值 / tab 未选 | **500** | 中间档，不抢主体也不虚 |
| tab 选中 | **600** | 与未选拉开 |

判据一句话：**「这行字要不要压住周围？」**——要，就 600；只是陪衬，就 400。**层级靠字重，不靠无意义的宽字距。**

## 4. 细节纪律

这几条是「有设计感」和「没设计感」的分界线，实现时必须遵守：

- **分割线一律 hairline**——1px，颜色用 `--bd` 而不是 `--bd2`。粗线是廉价的头号来源。
- **所有数字 `font-variant-numeric: tabular-nums`**——包括进度、词数、间隔、统计。数字跳动会毁掉排版。
- **小标签分两类**：拉丁文 `uppercase` 用宽字距（+3px，报纸法则，只适用于拉丁）；**中文标签一律 ≤1.1px**。中文全角字本身带内边距，再加宽字距是拉丁惯例的误用，只会显松散——**层级靠字重不靠字距**（见 §3 字重）。唯一例外是 10px 级「章印式」小节标签可留到 2.2px 作装饰，但仍不得用字距去冒充层级。
- **标记不用圆点也不用纯色块**——底部栏选中态用「**朱笔横痕**」（有起收笔的 30×4 笔触，切换时滑动），状态点用内描边小印（`inset` 描边）。圆点太软，纯色块太廉价。
- **图标 stroke-width 1.5**，不填充，tab 图标 22×22。
- **例句用衬线斜体**，关键词不用加粗，用 `--tx1` 提亮或朱砂下划线。
- **不做渐变、不做长阴影**。卡片阴影极轻或只用 1px 描边。

## 5. 关键交互决策

### 5.1 新词与复习走两条不同的路（v2 新增）

v1 原型只有一张翻转卡 + 四档评分，这是个**语义缺陷**：一个从没见过的词，让用户在「重来 / 困难 / 良好 / 简单」里选，FSRS 的首次评分语义是崩的——Again 表示「忘了」，可你根本没记过。

拆成两张卡：

| | 新词卡 | 复习卡 |
|---|---|---|
| 顶部标签 | 首 次 接 触 | 复习 12 / 47 |
| 底部按钮 | 不认识 / 认识（**认知判断**） | 重来 / 困难 / 良好 / 简单（**记忆评分**） |
| FSRS | 首次评分为 Good 入队，具体 due 由首评决定 | 正常四档调度 |

### 5.2 卡正面只有「单词 + 音标」

不显示释义、不显示例句。正面信息越多，用户越容易在回忆之前被动接收，回忆强度下降。音标是发音线索不算答案，保留。

落地补充（2026-09-18）：正面还有三件不构成「答案」的东西——**朱笔横痕**（识别符）、**白文朱印**（只标「这张卡为什么现在出现」：`新词` / `易忘`，没有第三种含义就不盖章）、**发音钮**（48dp，正反面都可重听）。

### 5.3 评分按钮显示下次间隔（长度 + 数字双编码）

沿用 Anki 已验证的做法，并加一层视觉编码：条长表达量级，数字表达精确值。

**数字必须是真值**：早期版本把四档间隔写死成「10 分钟 / 1 天 / 4 天 / 12 天」，与这张卡的实际调度无关——那就不是编码，是装饰。现在由 `previewIntervals()` 现场算（新卡走 `gradeNewCard` 分支，与 `recordGrade` 保持一致，否则预览会骗人）。

### 5.4 「想不起来按重来」

FSRS 里 Hard 的语义是「想起来了但吃力」，Again 才是「没想起来」。新手普遍误用 Hard，导致调度器把没记住的词排到远期。评分区上方常驻提示行。

### 5.5 详情页纵向单列，不做内分页

不背单词用了「释义/例句/助记」分页 tab，观感整洁但查一个词要点三次。本设计单列滚动，一屏看全。排版按词典条目：编号 + 词性 small-caps + 释义。

### 5.6 熟词校准：不是一个功能入口，拆成两处

原本设计是首页底部一个「词汇量测试」入口。斟酌后的判断是：**它本质是冷启动校准，不是学习功能**，所以不管放首页还是设置页都别扭——

- 放首页：「未测」这个标签会永久挂着，变成噪音和心理负担
- 放首次启动强制做：60 题 × 3 秒 = 3 分钟，对一个还没建立信任的 App 是流失点
- 藏设置页：用户永远不会点，等于没有

拆成两件事：

| | 触发时机 | 形态 |
|---|---|---|
| **首次校准** | 未校准状态下点「开始学习」 | 先走 20 题（约 30 秒，右上角可跳过），做完直接接今日新词。不是一个独立关卡，是「开始学习」的第一段 |
| **熟词校准** | 随时，可反复 | 首页底部常驻入口，显示「已校准 N 词」的中性状态；设置页也可进 |

配套第三条：**「标为已掌握」是常驻动作，不是集中测试**。真正高频的场景不是第一次校准，而是「背 GRE 时遇到一个早就会的四级词」。这个入口分布在卡片背面、单词详情页、搜索结果、词库列表长按——随时可用。

因此首页底部不再是「未测」这种负罪标签，而是一个中性的、可反复使用的工具入口。

### 5.7 不做游戏化

无连续打卡徽章、无排行榜、无鼓励弹窗、无成就。统计页只给数据。

## 6. 首页：保留（v2.1 定案）

首页的价值是"做数量上的心理准备"，直接甩进复习队列少一个缓冲。v2.1 的两处增强：

- **进度环改为 20 格刻度环**——一格 = 今日一个配额，已完成填朱砂、未完成用 `--bd`。连续圆环只能表达百分比，刻度环能**数**，也更接近仪表盘的手感。
- **主按钮下方加预计时长**（「预计 18 分钟 · 含 20 题熟词校准」）——把抽象的"20 个词"翻译成时间承诺，这是降低放弃率最有效的一行字。

### 卡片翻转动效

## 9. 设计体系 v3 · 原理与尺度（2026-09 新增）

> 背景：审查发现圆角在代码中出现 **10 种取值**（文档规定 6/8/10，`12` 出现 5 次超上限）、按钮高度 **8 种**、动效**零实现**（原型有 500ms 翻转，App 里是 `useState` 瞬切）。结论：缺的不是古风元素，是尺度与动效两根支柱。

### 9.1 三条原理（可判定）

| 原理 | 含义 | 判据 |
|---|---|---|
| **臣服** | 单词是唯一主角，界面臣服于它 | 任何界面元素若比单词更抢眼，不通过 |
| **痕迹** | 朱砂只标记人的痕迹（批注、标记、评分） | 问「这是人留下的还是机器生成的」——机器生成的一律中性色 |
| **量度** | 量级必须有物理编码，不能只有数字 | 凡表示「多少 / 多久」的信息，必须有长度或面积编码 |

底线：**宽容 + 可达**（评分可撤销、主行动在下半屏单手可达区）——美观不得挤掉这两条。

### 9.2 尺度系统（`src/theme/tokens.ts`，唯一取值来源）

| 组 | 档位 |

动效曲线规范：**纸的物理性——慢而稳、有阻尼、无回弹**（翻转 500ms `cubic-bezier(.32,.72,.28,1)`）。不做 spring，纸不会弹。

### 9.3 古风版式（v3 原型「版式」开关可对比）

- **版框**：内容卡加 `1px --bd2` 描边——从「悬浮的白块」变「纸上的一页」。只给内容卡加，列表项加框会变表格。
- **天头 > 地脚**：卡内边距上 34 / 下 18（古书版式上留白大于下）。只用于固定高度卡片，滚动容器保持均匀。
- **界行**：释义区左侧 `1px --bd` 竖线（竹片缝）。
- **朱文印**：标记类元素（计数点、状态点）用「内描边印章」而非纯色块——`inset 0 0 0 1px` 内边，从色块变印章。
- **明暗对偶**：亮 = 竹简·宣纸（`--bd2 #DAD3C5` 压痕、朱砂沉 `#A8382A`）；暗 = 碑刻·拓片（`--bd2 #4A4339` 拓痕白边、朱砂提亮 `#E06859` 如印泥）。共用同一组令牌名，切换的是意象不是结构。

### 9.4 导航与过渡（v3 原型 · 底部栏重做）

**为什么不许用小红点**：7px 圆点是状态指示（未读），不是导航语言；5 格里各挂一个，等于把导航降格成开关，廉价且糊弄。选中态必须能被「一眼读懂 + 一眼看出移动过」。

| 元素 | 规格 | 理由 |
|---|---|---|
| 朱痕指示器 | 30×4 笔触（有起收笔，两端圆头），切换时滑动 `MOTION.tab = 300ms`，**与页面位移同一条曲线、同一个时长** | 「你在这里」是人的痕迹 → 用朱砂（合**痕迹**原理）；会滑动才看得出页面关系 |
| 图标 | 22px 线性 `stroke-width:1.5`、`currentColor`；选中转 `--ac` + `translateY(-1px) scale(1.06)` | 纯文字导航没有图形锚点，识别慢 |
| 标签 | 选中字距 `0.8 → 1.1`、色 `--tx3 → --tx1`（中文全角字，字距过宽是拉丁全大写报纸惯例的误用；只给 10px 级「章印式」小标签留 1.6–2.2px 宽字距） | 选中三重编码（色 + 字距 + 位移），不依赖单一颜色 |
| 栏高 | 内容 62 + 上 8 + 下 10 = 80（含安全区），单格触摸区 ≥ 62×栏宽/5 | 原 64px 内容区偏挤 |
| 栏上渐隐 | tabbar 顶部 22px 向 `--bg` 的渐变遮罩 | 内容不再被 1px 硬边切断 |

**页面过渡必须有方向感**：按故事流程 `home → learn → done → word → stats → set` 判前后，前进从右 18px 淡入、后退从左 18px（`340ms cubic-bezier(.32,.72,.28,1)`）。单向 fade 表达不了「进去了 / 退出来了」。
**底部栏自动跟随**：任何 `go(screen)` 都按 `data-t` 反查对应 tab 高亮并滑动朱痕；`done`（完成屏）无 tab，保持「学习」高亮——它属于学习流程的收尾，不该让导航跳走。

#### 9.4.1 落到 App 的转场（2026-09-18，主人反馈「切换很不舒服」）

原型是 HTML 里手写的淡入位移；真机上必须换成导航层的原生转场，否则方向感全丢。实测发现两处硬伤：

1. **根 Stack 没写 `animation`** → 走平台默认值。Android 默认是淡入，于是「首页 → 学习 → 详情」这种层层深入的路径，看起来像**页面在互相替换**，而不是「推进去了」。
   修法：`screenOptions={{ animation: 'ios_from_right' }}` —— **push 从右推入，pop 自动反向**（原生栈的 pop 就是 push 的逆放），方向感免费拿到；`ios_from_right` 在 Android 上给 iOS 风格右入、在 iOS 上就是平台默认，两端一致。
2. **tab 切换默认 `animation: 'none'`** → 内容瞬间替换，只有朱痕在滑。**一个 150ms 一个 380ms，等于「内容先跳过去、光标随后追上来」**——这正是「切换不舒服」的机制来源。
   修法：`animation: 'shift'`（按索引方向平移 50dp + 交叉淡入）+ 自定义 `transitionSpec`，并把朱痕从 380ms 收到 **300ms**，两者共用 `MOTION.tab` 与同一条 `cubic-bezier(.32,.72,.28,1)`。**判据：同一个动作里的两半，时长必须相等**，否则读起来就是两次动作。

> **另外**：`lazy: false`。四个 tab 首次挂载都要各跑一次同步查库，默认 lazy 会把这笔开销压在**第一次切换的那一帧**上，正好落在转场起始处 → 掉帧。预挂载换掉这一下卡顿。

### 9.5 趋势对齐（iOS 26 Liquid Glass / Material 3 Expressive，2025–2026）
> 2026-09 核查两家最新设计语言后，对其可融合朱批的部分做了取舍。原则：**取其神不取其形**——形态语言（玻璃、大圆角、弹簧）会破坏纸/墨调性，但架构与纪律（分层、同心、触摸目标、hero、垂直韵律）值得吸收。

**吸收的（落到原型）**
- **控制层 / 内容层分离（苹果）**：底部栏、评分条是「控制层」，浮于内容之上；内容（单词）永远是主角（合**臣服**原理）。
- **同心圆角（苹果 concentricity）**：嵌套圆角跟随周围几何，内半径 < 外半径。
- **触摸目标 ≥ 48dp**（iOS 44 / Android 48，取严）：所有可点元素 ≥ 48。
- **内容分组容器（谷歌 containment）**：相关信息进同一容器，靠留白与最亮表面突出重点。
- **hero moment（谷歌）**：全产品只 1 个高潮——完成屏朱印「盖下」，短暂、有分量、不重复。
- **垂直韵律 / 字号阶梯（两家都强调 typography rhythm）**：分层靠**字号 + 颜色**，不靠无意义的宽字距；中文全角字不该照搬拉丁全大写的 2px 字距。

**没吸收的（会毁调性）**
- Liquid Glass 透明/折射材质——与纸不透明、墨沉的物质感冲突。
- 动态多色强调——破坏「朱砂只标人的痕迹」的单色体系。
- 盲目放大圆角——古书不该有塑料感，卡片圆角 12 封顶。
- 弹簧回弹——纸不会弹，只用阻尼 settle（无过冲）。

### 9.6 实现纪律（原型已落地，App 落地时照此）
- **触摸目标**：iconbtn 48 / soundbtn 48 / undo 钮 48 / tab 62 / 列表项 58（dp）。
- **同心圆角**：card/stat/grid3/fce = 12；按钮/评分 = 10；chip = 6；switch = 24 圆；嵌套内 < 外。
- **hero**：完成屏 `.sealbig` 落印（`stamp` .52s 阻尼，scale .72 + 旋 -4°→0，无回弹）；`grid3` 三格错峰 `rise`。
- **按压反馈**：按钮 scale .985/.96、tab scale .96，无生硬瞬切。

### 9.7 主人验收反馈修正（2026-09-18）

- **字重太细 = 廉价**：「很多字体都太细，没力量、简陋」。修正见 §3「字重」——标签/按钮/标题/数字全局提到 600，正文留 400。**旧结论「中文层级不靠字重」作废。**
- **「易忘」标签太简陋**：裸竖排两字无装饰 = 像随手贴的标签。改为**白文朱印**——30×46 朱底纸字小方章（宋体、600、方角），有古书批点的分量感。
- **打卡记录看不懂**：「我没看懂你这些格子代表什么」。35 格无标注热力图 → **月度日历**：星期表头（日一二三四五六）+ 每日日期数字 + 朱砂明度四档 + 脚注「9 月 · 打卡 15 天 · 连续 12 天」。**判据：可视化的每一格必须自明——没有表头 / 日期 / 刻度的格子等于谜语。** 格子收窄居中（max-width 252），不做无意义的大空格。
- **删除冗余**：统计 hero 右侧的周环（与副文「本周 4 / 7」重复）已删——**功能删除要彻底：样式 + HTML + 函数 + 调用一起删，不留死代码**。

### 9.8 落地实录：原型 → App（2026-09-18，全部界面）

原型是 HTML/CSS（有 SVG、`color-mix()`、`gap`），App 是 RN（**无 react-native-svg、无 reanimated**）。以下是逐个「用现有能力等价实现」的判据，不是妥协记录。

**刻度环（`ScaleRing`，纯 View 逼近弧段）**
原型用 20 段 SVG 弧。RN 侧改成 20 根**贴切线的直条**绕圆心旋转。可行性有量化依据：段弧长 ≈ 20dp 时，直线弦与圆弧的矢高差 < 0.7dp（肉眼不可辨）；段数少时（配额小）单条跨弧过大会露多边形感，故每段再按 ≤9° 切分并让子条重叠 0.6dp 消接缝。实测矢高：配额 5/8/10/20/30/40 时分别为 0.24/0.19/0.19/0.19/0.09/0.19 dp——一律不可见。

**打卡日历（`color-mix` 与 7 列网格）**
- `color-mix(in srgb, ac 15%, bg)` → `src/lib/color.ts` 的 `mix(from,to,t)`（#RRGGBB 线性插值）。
- **7 列不用 `gap`**：`width: 14.2857%` 叠 `gap: 5` 会溢出换行、第 7 天掉到第二行。改为「外格 1/7 宽 + 2.5dp 内衬」，表头复用同一外格结构才对齐。
- **对比度实测修正**：日历格文字原按原型用纸色字，但第 3 档底（`#c17468`）与纸色对比度只有 3.20（暗色 2.99），低于可读线。改为**只有最深的第 4 档用纸色字**（白文印），1–3 档一律 `tx1`。四档底明度实测：亮 219/178/132/79，暗 34/60/90/124（单调有序，这才是「量级」）。

**评分撤销（原型只是 CSS 收起，App 必须真回滚）**
`recordGrade` 返回评分前快照（cards 整行 + 刚插入的 `review_logs.id` + 当日 `daily_stats` 键）；`undoGrade` 三张表一起还原。**计数归零的当日行必须删掉**——否则它会算作「打过卡的一天」，把连续天数灌水。撤销条只在「刚评完 + 还没翻下一页」时出现，翻页即收起（它服务的是手滑，不是历史编辑）。**最后一张卡也要能撤**：完成屏保留「撤销上一次评分」入口，否则最后一下手滑不可逆。

> **撤销返回的索引不能用 `idx - 1`**（此处踩过坑）：中途评分后 `idx` 会 +1，`idx-1` 正好是刚评那张；但**评完最后一张时 `idx` 停在原地没 +1**（直接进完成屏），此时 `idx-1` 会退到**倒数第二张**——用户看到的是「撤销后换了张卡」。正解：撤销态里记住 `at`（评分时的索引），还原时 `setIdx(at)`。

**完成屏（一屏一事 = 收尾）**
朱印落印 → 三格数据 → 出口强弱刻意：先「看看坚持了多久」（正反馈），再「回到今日」（安静退出）。**`words === 0` 时不庆祝**，改渲染「今日已清空」安静版——给空成绩单盖「今日已毕」是撒谎。

> ⚠️ 落印的**具体做法**已在本节之后被两次改写：第三轮把回弹交给插值停点（§9.12①），第四轮推翻为三段独立时长 + 真下落位移（§9.13①）。这里只保留「这一屏要什么」的结论，机制以 §9.13 为准。

**朱砂只标人的痕迹（一次拨正）**
详情页例句原来是 2px 朱砂左栏。例句是词典语料 = 机器生成的，**不该用朱砂**；已换成 1px `--bd` 界行。朱砂留给：评分「重来」、白文朱印、进度、连续天数、主行动按钮。

**组件层（`src/components/ui`）**
`Card` / `Label` / `Kicker` / `Btn` / `Hair` / `Progress` / `StrokeBar` / `Seal` / `SealMark` / `StatCell` / `RowItem` / `Chev` / `BrandBar`。设置页与工具页的列表行、卡、按钮、小标签全部改走原子——设置页最容易长成一堆各写各的样式。

**残留与边界（明确写下，避免下次误判）**
- `RADIUS` 管版面构件（卡、按钮、条、格）。**图标内部的亚像素几何**（如 1.2dp 细条、1.5dp 书脊）虽也从档位取值，但不受「只此七档」的语义约束。
- 尺度收口做了两轮，现在 **间距一律 `SPACE`、控件高度一律 `CONTROL`、尺度字号一律 `FONT`**；全仓库扫描确认**无硬编码色、无裸字重、无裸 `borderRadius`**（唯二含十六进制的是 `theme/tokens.ts` 本身与 `db/queries.ts` 里一个自定义词库的落库色常量）。
- **剩下来的字面值都是「组件专属尺寸」，不是漏网**：印章 72、完成屏三格占比、朱痕 `top: -1`、日历格内衬 2.5、图标内部的亚像素几何（1.2 / 1.5 / 1.8dp 细条）。这些值属于该组件自身的构造，套令牌反而失真——**判据：这个数换到别的地方还成立吗？不成立就是私有尺寸。**
- **验证方式**（无浏览器截图路线时仍然可做）：`tsc --noEmit` 零错误 + `expo export --platform android` 打包通过（1284 modules）+ 关键几何/对比度的数值核算脚本。**类型检查顺带保证「没有悬空的样式引用」**——`styles.x` 在 `StyleSheet.create` 删除后会直接报错。

### 9.9 多机型弹性布局（2026-09-18）

主人反馈「适配多种机型大小做得不够好，长宽比各不相同，应该用弹性的空间布局」。屏幕差异有三个维度，**坏法各不相同**，得分开治：

| 维度 | 差异范围 | 写死值的坏法 | 治法 |
|---|---|---|---|
| 顶部（状态栏 / 挖孔 / 灵动岛） | 0 → 48+ dp | 写死 `paddingTop: 52`：在 48dp 挖孔机上**压字**，在无状态栏设备（平板分屏 / 桌面模式）上白留一条 | `useTopPad() = insets.top + SPACE.xl` |
| 长宽比 | 16:9 ↔ 21:9（可用高度差 20%） | 短屏被裁、长屏顶头空一大块 | 能用高度的构件按视口算尺寸（刻度环）；不能裁的内容必须可滚（完成屏） |
| 宽度（平板 / 折叠屏展开） | 320 → 900 dp | 卡片横跨整屏、一行塞 60 个汉字，行距再讲究也读不动 | `CONTENT_MAX = 520`，`useSideInset()` 把余量还给左右 |

**新增基元 `src/lib/layout.ts`**：`useTopPad()` / `useSideInset()`（额外留白，手机恒 0）/ `useGutter()`（绝对留白，手机恒 20）/ `useBottomPad()`（手势条避让）/ `CONTENT_MAX`。

> **纪律：这些 hook 在手机上必须零变化。** `useSideInset()` 在 ≤520dp 宽时返回 0，`useTopPad()` 在 32dp 状态栏机型上正好等于旧的 52 —— 否则就是拿「适配」当借口改设计。已用 7 种机型（320×568 → 884×1104）核算过：手机 gutter 恒 20、side 恒 0，只有平板/折叠屏才收列。

**哪些构件必须自适应，判据是什么**

- **刻度环**：`clamp(min(可用宽, 屏高 × 0.25), 156, 216)`。环不能自己吃掉半屏——高度要留给数据卡、主 CTA、校准行；环径变化时**环心数字、字距、圆环粗细按同一比例缩放**（不缩就会出现「小环装不下 58sp 数字、大环里数字显小」）。
- **打卡日历**：`min(可用宽, 336)`。上限的判据不是好看，是**语义**：7 列 + 5dp 内衬下 336dp 对应单格 43dp，正好压在 48dp 触控目标之下 —— 再宽就会被读成「可点的按钮」，与「这天打过卡」的陈述性语义冲突。实测各机型单格 29–43dp，全部达标。
- **完成屏**：内容高度随机型变（短屏 ~640、长屏 ~930）。改 `ScrollView + flexGrow:1 + justifyContent:center` —— **空间富余时整体居中**（不再顶头 + 底部一片空），**空间不足时可滚动**（短屏不会把「撤销上一次评分」裁掉，那是不可替代的出口）。
- **长词**：`numberOfLines={2} + adjustsFontSizeToFit + minimumFontScale={0.45}`。原来说「长词换行也比省略号好」，但换 3–4 行会把音标和喇叭挤出卡外；两行封顶、超出等比缩字，缩到 22sp 仍是全屏最大的字，主角地位不变。
- **装文字的控件一律 `minHeight` 不用 `height`**：RN 的 `Text` 默认跟随系统字号，固定高度 + 系统大字号 = 文字被裁掉半行。`minHeight` 在默认字号下渲染完全一致，只在文字变大时长高。**圆形（`width`+`height` 成对）不动**——那是形状不是容器。

**自检脚本 `tools/verify-design.cjs`（`npm run verify`）**：把上面这些判据写成 28 条断言（令牌纪律 / 尺度纪律 / 弹性布局 / 转场与长内容 / 抬升与量度 / 对比度），改坏就红。

> 为什么需要它：**设计体系的失效方式不是报错，是悄悄退化。** 顺手写回一个 `paddingTop: 52`、一个 `#C0452F`、一个 `height: 54` —— 代码照样跑、`tsc` 照样过，只有真机上才看得出「怎么又不对了」。断言是唯一能拦住这件事的东西。脚本只看代码不读注释（注释里常要引用旧的坏写法来说明为什么改）。

### 9.10 转场设计（2026-09-18）

主人反馈：「**页面切换会闪一道白光**，而且你得设计页面切换的动效啊，很生硬很劣质，要在细节上保持品牌调性」。

#### 白光不是动效问题，是「透光」

三层容器各自没有底色，淡入时一层层透过去，看到的是**原生窗口的白**：

| 层 | 默认 | 露白的时机 | 修法 |
|---|---|---|---|
| 原生栈卡片 | 白（Android 上取窗口色） | 卡片推进来的一瞬、以及被上层页面遮住的边缘 | `Stack` 的 `contentStyle: { backgroundColor: c.bg }` |
| tab 场景容器 | 透明 | 交叉淡入期间透过去看到下层（正是上面那块白） | `Tabs` 的 `sceneStyle: { backgroundColor: c.bg }` |
| tabs 布局根 `View` | 透明 | 最后一道透光 | 根 `View` 加 `backgroundColor` |

**判据：任何会做「淡入 / 交叉」的容器都必须自己有底色。** 淡入的本质是把不透明度从 0 拉到 1 —— 0 到 1 之间观众看到的是**下一层**；下一层是什么，取决于你有没有给它底色。

#### 同级切换：位移量是语义问题，不是手感问题

- 内置 `shift` 预设的位移是 **±50dp** + 通用 `inOut(ease)`。50dp 是「整页滑过去」的量，那是**走进下一页**的语义；用在同一层级的两个 tab 之间，语义不对，观感就是「一块被推来推去的硬纸板」——「生硬」的机制来源。
- 现在用自定义 `sceneStyleInterpolator`「**纸页轻推**」：方向感知 **±14dp** + 交叉淡入（原型页间位移是 18dp，tab 要更轻）。14dp 读起来是「这张纸被轻推了一下」：**眼睛先读到「内容换了」，再读到「有一点点方向」——顺序对了才不吵。**
- 曲线换成朱批主曲线（减速），时长仍与朱痕同值 `MOTION.tab = 300`。
- **判据：位移量表达层级关系** —— 同级越小越好（≤16dp），跨级才用整屏。

#### 纵深屏（栈屏）：系统负责卡片，我们负责内容

- 卡片推进是原生栈给的（改不了），**内容是唯一能设计的那一层** → `PageEnter`：内容比卡片晚半拍「显影落定」（`MOTION.enter = 240ms`，纯透明度）。
- **只做透明度、不做位移**：系统横向推 + 我们竖向浮 = **斜向运动** —— 两股力方向不同，这正是「业余感」的来源。内容在原地「显影」，只补系统缺的那半拍。
- **tab 屏不用 `PageEnter`**：场景自己已有交叉淡入，套两层会发飘。纵深屏才需要（它没有第二层动效可用）。
- 返回时不会重播：栈屏在 push 后仍挂载，`useEffect` 不再触发；返回的动效由原生 pop 负责。

#### 曲线收敛：全项目三条，且每条对应一个**物理情境**

动效的廉价感八成来自「**每条动效各用一个 ease**」—— 页面用 inOut、按钮用默认、印章再用一个，单看都还行，放一起就散。纸与墨的动作只有三种：

| 曲线 | 值 | 语义 |
|---|---|---|
| `EASE` | `[0.32, 0.72, 0.28, 1]` | 主曲线：起步快、收尾长 —— 东西**被推了一下**，外力已撤走，所以只会越来越慢（**无过冲，纸不会弹**） |
| `EASE_SETTLE` | `[0.22, 1, 0.36, 1]` | 收束：起步更急、收尾更缓 —— 印章落下只有一次，要「啪」地定住 |
| `EASE_FALL` | `[0.42, 0, 1, 1]` | 落体：起步慢、收尾快，即**加速**。它与 `EASE` 方向恰好相反，而这不是风格选择：下落是**重力**在做事，用减速曲线画下落，观众读到的是「有人把章轻轻放下去」而不是「章落下来」 |

第三条曲线是第四轮补上的，理由不是「想多一条」，而是**前两条里没有一条能描述自由落体**（详见 §9.13）。曲线仍然不许过冲。

曲线以**贝塞尔控制点（四个数）**导出，用时 `Easing.bezier(...EASE)`，令牌文件保持零依赖。**各处手写 `Easing.bezier(数字)` 已被断言禁止。**

时长分两族，各有语义：**「写」（朱笔，人的动作，有过程）** 与 **「盖」（印章，确认，已成事实）**。`press 120 / fade 200 / enter 240 / sheet 280 / tab 300 / flip 500 / stroke 260`（写）/ `sealTamp 150`（钤小印）/ `sealFall 200 + sealPress 90 + sealSettle 170`（落印高潮）/ `sealSpread 320`（墨洇）/ `shock 220`（纸面微震）。

#### 减弱动效（无障碍里最常漏的一条）

`useReducedMotion()` 读系统设置，动效**不是变慢，而是直接到位** —— 变慢对前庭敏感的用户更难受。已覆盖：页面入场、tab 位移（只留交叉淡入）、朱痕滑动、卡片 3D 翻转、完成屏落印。

#### 刻意没做的

`fullScreenGestureEnabled` / `animationMatchesGesture`：只在 iOS 生效、本机无法验证，且会**改变 iOS 上 push 的默认动画**（官方文档明说「默认 iOS 手势动画不可复现」）。iOS 的边缘返回手势本来就是跟手的 —— **不拿无法验证的改动冒充打磨**。

### 9.11 第二轮验收修正：投影 / 词库灰 / 长按钮（2026-09-18）

主人反馈原话：「**现在白色模式下，统计和设置切换的时候各个框的阴影会显示很久，体验很糟糕**，另外**词库的这些为什么都是灰色的，搞得死气沉沉**，点进去有个『只背这一纲』**超级长**，你是不是设置的左边顶到头右边顶到尾一个超级无敌长的按钮，学生都不会做这种丑按钮吧」。

三条毛病，机制各不相同，也都不在「好不好看」这一层。

#### ① 投影的毛病不是「重」，是「不消隐」

现象只在**亮色**下出现（暗色不投影），且出现在 **tab 切换**时（统计 ↔ 设置）。追下来只有两处用到投影：共享原子 `Card`（设置页用了 4 张）与 `ReviewCard`（复习卡）——两者都是 `scheme === 'light' ? SHADOW.card : null`。

真正的机制不在我们的代码，在 Android 的平台投影：

| 事实 | 后果 |
|---|---|
| `elevation` 是**平台阴影**，RN 只映射 `shadowColor`（API 28+）；`shadowOpacity / shadowRadius / shadowOffset` **在安卓上被忽略** | 设计稿写的「5% 极轻阴影」在真机上**根本不存在**，落地的是平台自己那层重得多的黑边 |
| 投影由平台**单独绘制**，不参与祖先 `opacity` 的合成 | tab 交叉淡入时旧屏场景淡出、内容消失了，**卡片的投影留下来** —— 就是「阴影显示很久」 |
| 同一份令牌在两端表现不同 | iOS 柔和阴影 / Android 滞后黑边，一套令牌两种观感 |

**做法：删掉 `SHADOW` 与 `LAYER` 两个令牌**，抬升一律用两件事表达：

1. **面比底亮一档**：亮 `sf #FDFCFA` 压 `bg #F7F4ED`，暗 `sf #1B1A18` 浮 `bg #131211`（这本来就是原型的分层手法）
2. **1px 描边**（`--bd`）

判据：**任何依赖平台合成层的"样式"都要先问它在交叉淡入里怎么表现。** 纸本来就没有会动的影子，抬升是「材质差异」，不是「光照」。

#### ②「中性」不等于「看不见」——量度必须落在墨阶上

词库是机器生成的分类，不给它彩色（朱砂只标人的痕迹，§9.8 已拨正）。但**执行把「中性」做成了「看不见」**：

| 元素 | 原来 | 实测对比度 | 现在 |
|---|---|---|---|
| 条填充 | `bd2`（轨道是 `pg`） | **1.25:1** | `tx2`（选中 `ac`）→ 3.75:1（暗 3.70:1） |
| 轨道 | `pg`（≈页面底色） | 1.07:1 | `bd2`（回归原型 `.rw .bar` 取值，量度的「满额」要有容器） |
| 标记 | 实心灰圆点 `tx3` | —— | 1px 内描边小方印（朱文印），描边 `tx2`；选中才落朱砂实底 |
| 名称 / 词数 | 15px 400 / 13px 400 | 字重不足 | `tx1`·500 / 衬线 `tx2`·600 tabular |

**判据：中性靠墨阶（tx1 > tx2 > tx3）表达层级，不靠「更淡的灰」。** 一个填色若与它的轨道只差一档明度，那条「量度」就是装饰 —— 而量度是可判定的（§9.1 三原理），所以这条判据写进了断言，并且**直接算对比度**而不是检查颜色名。

另外顺手补上原型 06 屏写过、App 漏掉的一条：自定义导入的词表用**虚线方印**区分（`tags.kind = 'custom'`）——那是你自己造的清单，与内置考纲不是一回事。

#### ③ 容器宽度 ≠ 按钮宽度

`wordlist` 的「只背这一纲」写在根容器（`flexDirection: column`）里，默认 `alignItems: stretch` → 按钮左边缘到右边缘。**这是把「容器占多宽」当成了「按钮该多宽」。**

- 这屏的主行动不是它（这屏是「翻词表」），一个顶满整行的长条会**把浏览页读成「一屏只有一个按钮」**；
- 改为 `alignSelf: 'center'` + `minWidth 200` + `paddingHorizontal 32`，两态同宽、切换不跳（文案同步收敛：`只背这一纲` / `✓ 在背 · 去首页`）。

**判据：按钮宽度由内容决定，只有「这一屏只有这一个动作」时才允许顶满整行**（首页主 CTA 属此类，词表页不属）。

#### 新增断言（24 → 28 条）

| 断言 | 拦住的退化 |
|---|---|
| 不用投影（0 处 `elevation` / 0 处 `SHADOW`） | 有人顺手把 `SHADOW` 加回来 |
| 词库细条用墨阶填充 | 条色被写回 `bd2`（长度立刻不可见） |
| 行内动作按钮不顶满整行 | `alignSelf` 被删回默认 `stretch` |
| 对比度达标（前景 3:1 / 同条两段 2.5:1，亮暗各一套） | 令牌值被调淡到「看不见」——**直接解析 `tokens.ts` 算 WCAG 对比度**，不检查颜色名 |

> 第 4 条的阈值分两档：**前景压背景**（文字、描边）取 3:1；**同一条上的两段**（填充 vs 轨道）取 2.5:1 —— 后者不是前景/背景关系，且两段色相相距很远（朱砂 vs 墨），暗色下 `ac/bd2` 实测 2.70（再抬轨道就与页面底色分不开了）。

#### 数值核算（改前 → 改后，亮色 / 暗色）

| 对 | 改前 | 改后 |
|---|---|---|
| 未选条填充 / 轨道 | **1.25:1**（亮）· 1.99:1（暗）—— 等于没画 | 3.75:1 · 3.70:1 |
| 未选条填充 / 页面底色 | 1.36:1 · 1.91:1 | 5.08:1 · 7.07:1 |
| 方印描边 / 页面底色 | 2.53:1（原实心灰点，`tx3`） | 5.08:1 · 7.07:1 |
| 选中条 / 轨道 | 5.41:1 · 5.37:1 | 4.32:1 · **2.70:1**（轨道加强的代价，见上方阈值说明） |
| 名称 / 页面底色 | 16.59:1 · 15.76:1（一直够） | 16.59:1 · 15.76:1 |

### 9.12 第三轮：设计修复与品牌升级（2026-09-18）

这一轮的要求分三层：**P0 修硬伤、P1 一致性与可读性、P2 品牌与故事**，并附带一份「必须保留」的资产清单（衬线大字词典排、纸底朱砂气质、印章与打卡日历、学习→完成→统计闭环、预计分钟/撤销/熟词校准）。落地的判据只有一句：**这轮之后，它要从「一个红色主题的学习 App」变成「那个盖章背单词的背呗」。**

改动以**渐进**方式进行——没有重写任何一屏，全部是在既有组件结构上换 token、换原子、换文案。

---

#### P0-1 数字折行：把「排版契约」做成组件，而不是逐处打补丁

现象是「统计数字在窄屏被折断 / 截断」。真正的问题是**数字在代码里没有唯一入口**——每屏各自写 `<Text>` + 各自的字号，于是「不许折行」「要等宽数位」「要千分位」这三件事没有任何一处能统一保证。

做法是把契约固化成两个原子（`src/components/ui/index.tsx`）与一个工具（`src/lib/num.ts`）：

| 层 | 做法 | 为什么 |
|---|---|---|
| 排版 | `Num`：`numberOfLines={1}` + `adjustsFontSizeToFit` + `minimumFontScale` + `fontVariant: ['tabular-nums']` + `flexShrink: 1` | 「不折行」在 RN 里不是 `white-space: nowrap`（那是 Web）——移动端的等价物是**单行 + 自动缩字**，外加允许被压缩 |
| 文本 | `fmtNum()` 手写千分位 | **不用 `toLocaleString`**：它按设备区域设置输出（同一份数据在不同手机上可能没有分隔符）。数字的排版是设计决定，不能交给系统区域设置 |
| 数字+单位 | `NumUnit`：`flexDirection: row` + `alignItems: baseline`，单位走 `FONT.unit`(12) 且 `flexShrink: 0` | 「18 词」的「词」与读数**共基线**才像排印；单位必须比读数小一档；单位不允许被压掉（压掉读数就失去量纲） |

> `Num` 的 `minimumFontScale` 是最后一道闸：即便如此，缩到 `0.6` 就不许再缩——再小就不是「读数」了。读数是这一屏的主角，宁可容器放宽。

#### P0-2 深色重做：「墨纸」体系

原深色有两个错：**色相漂成珊瑚橙**、**底是纯黑**。数值与判据见 §2。要点是把两个主观判断都写成**从 `tokens.ts` 实读取值的断言**（实算 HSL 色相与 WCAG 对比度），而不是「看起来差不多」。

#### P0-3 喇叭图标：一个按钮的唯一文案

原图标是「圆环套实心圆点」，在图形语言里那是**录制 / 电台 / 状态灯**——没有一个读音叫「播放」。而**图标是这个按钮唯一的文案，它认错就等于这个功能不存在**。四处复制（单词页 / 复习卡正反面 / 校准 / 词汇测试），于是改成共享原子 `SoundIcon`，并对齐 Material `volume_up` 的几何。

**这一条是这一轮里最值得记下来的部分**：代码改完 `tsc` 绿、断言绿，但把对照稿渲染出来一看，图标仍然是个认不出的色块。真因有两条，都不是看代码能发现的——

| 结论 | 实测过程 |
|---|---|
| 喇叭口必须是**梯形**（左沿与箱体等高、右沿向两侧张开） | 用 `borderLeft` 着色画喇叭口，得到的是**左边宽、右边尖**的三角形 → 整体读成「▶ 播放键」。做一个 8 组 border 组合的实测页，才确认「`borderLeft` 透明 + `borderBottom` 着色」这个组合得到的正是梯形所需的那一半，两片镜像合成喇叭口 |
| 声波必须是**弧** | 原写法是「上+右边框的正方形转 45°」——渲染出来是个**菱形环**。改成「圆形只留 `borderRight`」= 一段干净的 90° 弧，两道弧共用圆心、只放大直径，自然同心 |
| 14px 及以下只留**一道**弧 | 复习卡背面用小图标（14px）。两道弧在这个尺寸糊成一个色点，一道反而清楚——图标不是等比缩小的图，小尺寸要**减笔** |

顺带解决了一个已有依赖风险：`@expo/vector-icons` / `react-native-svg` 都不在 `node_modules` 里，`expo-symbols` 只在 iOS 有效。所以**纯 View 手绘是对的选择**，但它必须有可验证的几何（现在入断言）。

#### P2 品牌锚点：朱砂 + 印章

目标是把「红色主题」变成「盖章」。四项落地：

**① 完成页落印（`DoneView`）** —— 印章砸落、轻微回弹、纸面微震。

> ⚠️ **本节下面三条已被 §9.13① 推翻，保留在此仅作记录。** 主人验收时的原话是「完成页盖章动效**根本和描述完全不符，看起来只是屏幕抖动了一下**」。原因：一条急收曲线承载多个插值停点 + `sealStyle` 里根本没有 `translateY`。**「描述里写了」不等于「屏幕上发生了」。**

- 回弹**由插值停点表达**，不让共享曲线过冲：`STOPS = [0, 0.72, 0.88, 1]` → `scale [0.72, 1.08, 0.98, 1]`、`rotate [-7°, 0, 0, 0]`，即「下落 → 触纸略放大 → 回弹（比终态略小）→ 定住」。**曲线一过冲，全项目每一处入场内容都会跟着弹**——所以过冲只能属于这一个元件。
- 微震是**落印的后果**：`Animated.delay(MOTION.seal * SEAL_IMPACT)` 之后才起算，幅度 1.6dp / 1.1dp。**超过 3dp 就从「纸被震了一下」变成「屏幕在晃」**。印章与文字包在**同一个**会震的容器里——分开震会露馅。
- `SEAL_IMPACT` 单列成常量而不是写死在插值里：回弹曲线的形状与「微震从哪一刻开始」是**同一件事的两个读法**，改一个必须改另一个。

**② 打卡日历印章化（`stats`）** —— 一个打卡日 = 一枚朱印；图例用**与格子同一种印记**并标「少 / 多」。**图例画的是色块、格子画的是印记，读者就得自己做一次映射——图例的意义正是免掉这一步。**

> ⚠️ **本节「印面边长按当日量四档递增」已被 §9.13③ 推翻。** 主人原话：「你好像简单改成颜色块的大小，我觉得这是很错误的……**大小绝对是要一样大的，不然大大小小放一起很不好看**」。


> 浓度用**印面大小**而不是朱砂深浅：先试过「浅朱 → 浓朱」的明度梯度（第一版就是），但浅朱压纸底只有 1.4–2.7:1，而印面只有几 dp——**一个对比度不足 3:1 的小点在屏幕上不构成「这天打过卡」的陈述**。
>
> 第三轮复核时发现印记整体**偏小**（原 4–8.2dp）：日历里还看得见，图例里四枚样本连递增都读不出来——**一个看不出差别的图例等于没有图例**。基准提到 6dp（仍稳稳落在 48dp 宽的日期格内）后递增一眼可辨。

**③ 启动页与图标** —— `BootScreen` 重做成「第一枚印章」（朱砂方章 + 内描边 + 竖排「背呗」+ `正在打开词库…`）；`app.json` 的 `adaptiveIcon.backgroundColor` 由离品牌的 `#E6F4FE` 改纸色 `#F7F4ED`。

> 这里刻意**没有**引入 `expo-splash-screen` 插件：它不在 `node_modules` 里，为一个启动屏去装依赖可能让构建不可用。纯 JS 启动屏可回退、零依赖。

**④ 文案口语化** —— 呼应「呗」的轻松语气。工程注释一律改用户语言：

| 原 | 现 |
|---|---|
| `柱高 = 当日新学 + 复习次数` | `柱子越高，那天背得越多` |
| `预计 18 词 · 约 5 分钟` | `大概 5 分钟 · 今天 18 个词` |
| `已装载 30565 词` | `已装载 30,565 词` |
| `✕ 背全部` | `全部词库` |
| `标 为 已 掌 握` | `标为已掌握` |
| `保 存 设 置` | `保存设置` |

### 9.13 第四轮：落印与印记（2026-09-18）

主人验收第三轮后给了四条否定 + 一条要求：

> 「你的预览是显示选择哪种辞书会用红色标记，但是**实际上并没有看到这个效果**，完成页盖章动效**根本和描述完全不符，看起来只是屏幕抖动了一下**。打卡日历印章化……但是你好像简单改成颜色块的大小，我觉得**这是很错误的**，需要仔细打磨优化，**大小绝对是要一样大的，不然大大小小放一起很不好看**。很多动效可以结合**朱批和盖章**这两个行为去延伸拓展你思考一下。」

四条否定里两条是**真 bug**、一条是**设计方向被推翻**、一条是**新增要求**。它们指向同一个根因：

> **把「设计意图」写进了代码，却没有任何一步验证意图是否真的抵达了屏幕。**
> 注释、文档、断言都可能只是在描述一个「打算」，而不是一个「事实」。

#### ① 词库「在背」标记看不到 —— 过期快照

`library.tsx` 在**渲染期**一次性求值 `getTags()` / `getWordCount()` / `getStudyScope().tagId`：

```tsx
const tags = getTags();
const total = getWordCount();
const scopeTagId = getStudyScope().tagId;   // ← 问题在这
```

tab 屏**切走不卸载、切回不重挂载**，所以这三个值永远停在首次进入那一刻。学习范围是在 `wordlist` 页改的，改完回到词库时组件早就在那儿了 —— 标记于是**永远不出现**。

判据（可复用）：**凡是「别处可改、这里要显示」的值，都必须走聚焦重读。**

```tsx
const [scopeTagId, setScopeTagId] = useState<number | null>(() => getStudyScope().tagId);
useFocusEffect(useCallback(() => {
  setTags(getTags()); setTotal(getWordCount()); setScopeTagId(getStudyScope().tagId);
}, []));
```

这个坑本仓库踩过第二次 → 已固化为断言（三个读库的 tab 屏，查询函数只允许出现在 `useState` 初值或 `useFocusEffect` 回调里，不许有 `const x = getXxx()`）。

> `settings.tsx` 里也有 `const s = getSettings()`，但它是**只给 `useState` 初值用**的（用户正在编辑的 stepper 状态），加了聚焦刷新反而会**清掉用户没保存的输入** —— 所以它不在断言范围内。**同一句代码，是不是 bug 取决于它后面接什么。**

#### ② 落印：**一条曲线只能塑造一段动作的形状，不能承载一条时间轴**

旧做法：`stamp` 0→1 交给**一条** `EASE_SETTLE` 急收曲线跑满 520ms，再用插值停点表达四个阶段：

```
STOPS = [0, 0.72, 0.88, 1]  →  scale [0.72, 1.08, 0.98, 1] / rotate [-7°, 0, 0, 0]
```

两个错，都可算：

1. `cubic-bezier(.22,1,.36,1)` **前 20% 的时间就走完约 80% 路程** → 停点 `0.72` 落在约 **第 15ms（≈1 帧）**。落、压、弹、停四件事全挤进最后几十毫秒。
2. **`sealStyle` 里根本没有 `translateY`** —— 只有 `scale` 与 `rotate`。于是「章掉下来」退化成「章在原地变大」。

结果：屏幕上唯一在动的就是那 1.6dp 的纸面微震。观众看到的就是「抖了一下」，完全对得上主人的描述。

修正 —— **三段各自独立的 duration**：

| 段 | 令牌 | 时长 | 曲线 | 做什么 |
|---|---|---|---|---|
| ➊ 落 | `sealFall` | 200ms | `EASE_FALL`（加速） | `translateY −30 → 0` + `scale .88 → 1.09` + `rotate −6° → 0` |
| ➋ 压 | `sealPress` | 90ms | `EASE_SETTLE` | 触纸：比例过冲到 1.09（印泥被压开） |
| ➌ 收 | `sealSettle` | 170ms | `EASE_SETTLE` | 回弹到 0.985 再定住 |

配套四条：

- **微震与「墨洇」都是后果，不是动作**：起点统一为 `Animated.delay(MOTION.sealFall)`。墨洇 = 贴印边 1.22× 的一圈朱色细线，320ms 淡出。
- **字在印落定之后才显影**（`delay = sealFall + sealPress`）。**次序就是语义**：先落印再显字 = 批注（这一屏要的）；字先铺好、印后盖上 = 表单盖章。
- 微震仍作用在**整块内容**上（章压在纸上，纸动章也动，分开震会露馅）。它之所以不再被读成「屏幕抖了一下」，是因为章自己先有了 30dp 的下落 —— **微震从「屏幕上唯一的运动」退回了它本来的位置：落印的余韵。**
- `SEAL_IMPACT` / `STOPS` **一并删除**。不留旧名字，否则下一个改这屏的人会顺着它把插值停点写回来。

> **可复用的结论**：把「多个阶段」表达成一条曲线上的多个停点，只有在曲线几乎线性时才成立。想要阶段感，就必须给每个阶段自己的 `duration`。

#### ③ 印记：尺寸恒定，浓度靠**墨量**

第一版把浓度编码成**印面大小**（6 → 10.8dp）。主人的否决引出比「好不好看」更硬的编码原则：

> **重复出现、且必须并排比较的元素，不能用尺寸编码差异。**

日历里 30 格是**一排读数**。尺寸一多样，眼睛去比的是「哪个更大」，而不再是「哪天的墨更重」；何况相邻两档只差 1.6dp，**比大小本身也不成立**。

改为**同尺寸（9dp）+ 墨量分档** —— 篆刻本来就有现成的语汇：**同尺寸印面，墨越满越重**。

| 档 | 形制 | 画法 |
|---|---|---|
| 1 少 | 细边朱文 | `borderWidth 1`，中间几乎全空 |
| 2 多 | 粗边朱文 | `borderWidth 1.9`，中间只剩一线 |
| 3 满 | 满墨白文 | 印面全朱 + 一道**纸色**内框（白文印的真实结构：朱是底、「字」是纸） |
| 0 | 未打卡 | **不画印**（描一圈虚线等于凭空多塞 30 个元素；空白的克制本身就是「还没盖」） |

- **为什么只分三档**：9dp 印面上「细 / 中 / 粗」的边界已接近可辨极限 —— **读不出来的分辨率不是分辨率，是噪声。**
- 分档规则放进令牌层 `stampInk(total, max)`，而不是写在各屏里：**日历格与图例必须用同一条规则**，否则图例就会和日历说不同的话（而图例的全部意义正是「不用反查」）。
- `Seal` 原子从 `variant: 'solid' | 'text'` 改为 `ink: 1 | 2 | 3` + `paper`。`paper` 是**印下面那张纸**的颜色：白文内框是纸色实体，永远取 `c.bg` 会在卡面（`c.sf`）上暗一档，读成「一个空心框」而不是「白文印」。
- 白文内框的比例在**大印**与**小印**上是两套：大印（启动页 64dp / 完成页 72dp）用**固定 1px 细线 + 5–7% 内缩**（那是「刻痕」），小印（9dp）用 **22% 内缩**（那才留得出 ≥5dp 的洞）。**同一个视觉概念在两种尺度下的正确画法不同 —— 这不是不一致，是「线」与「洞」的区别。**

#### ④ 动效语汇：**写** 与 **盖**

按主人要求把动效延伸到朱批与盖章两个行为上，先立判据，再落地。判据只有一句：

> **这个动效是在「写」，还是在「盖」？**

| | 写（朱笔） | 盖（印章） |
|---|---|---|
| 语义 | 人的动作：有过程、有方向、可撤销 | 确认：瞬时、块、已成事实 |
| 视觉 | **线**、展开、留锋 | **块**、压印、不留过程 |
| 时长 | 慢（`stroke 260`） | 快（`sealTamp 150` / 落印三段） |
| 曲线 | 主曲线（快起慢收 = 收笔减速 = **留锋在时间上的表达**） | `EASE_SETTLE` |

落地四处：

| 位置 | 行为 | 实现 |
|---|---|---|
| 详情页朱笔横痕 | **写** | `width 0 → 168`（`Animated.View` + `useNativeDriver:false`，宽度是布局属性），起点比页面入场晚 40% —— 字先到位，笔才落得下去 |
| 词库「在背」 | **盖** | `scale 1.24 → 1` + 淡入，`sealTamp 150`。起始比例**比 1 大**：印落在纸上的一瞬比静止时大 |
| 打卡日历印记 | **盖** | 同上，且**错峰**（只给打了卡的日子排拍子、封顶 12 拍 ≈190ms）；聚焦时重播 |
| 完成页「今日已毕」 | **盖**（高潮） | 落 / 压 / 收三段 + 墨洇 + 纸震 |

> 这套语汇与既有的 `SealMark` / `Seal` 是同源的：**朱文印只留轮廓 = 线 = 写；白文印满墨 = 块 = 盖。**

#### 断言改写（47 → 49）：**被推翻的设计，必须改写为它站岗的断言**

这一轮最重要的方法论。旧的两条断言保护的**正是被推翻的做法**：

| 旧断言 | 判据 | 问题 |
|---|---|---|
| `打卡日历印章化（满墨印记 + 图例同形）` | 有 `stampSize`、有 `stampSize(lv)` | 给「印记用大小编码」站岗 |
| `落印有冲击点与纸面微震` | 有 `SEAL_IMPACT` 且 `SEAL_IMPACT = 0.72` | 给「插值停点承载时间轴」站岗 |

**只补新断言而不改旧断言，等于让旧断言继续挡住修正。** 改后的判据方向相反：

- 印记：从「有这个函数」→ **「全屏只有一个尺寸取值」**（`size={...}` 的每一处都必须等于 `size={STAMP.size}`，且 `stampSize` 在代码与令牌里都不许再出现）。
- 落印：从「停在 72%」→ **「落这一段有没有 `translateY`」**（外加三段各自的 duration、微震 delay = `sealFall`、`SEAL_IMPACT` 不许复活）。

新增两条：**写/盖动效语汇**、**tab 屏无过期快照**。

#### 复核方式升级：CSS 负延迟**定格分镜**

上一轮的复核是「对照稿 → 无头 Edge 截图 → 逐块看」。这一轮加了一步关键做法：

> 用 `animation-delay: -Nms` + `animation-play-state: paused`（配 `animation-fill-mode: both`）把**真实动画定格成一条分镜带**，并把每帧的状态写进图注 —— 例如「200 ms · 落 · 洇圈未起」。

好处有三：① 帧来自真实 keyframe 与真实曲线，不是「我觉得这时候应该是这样」；② **图注让稿子自检**（状态写错了在图上就能读出来）；③ 动画量（时长、延迟、位移、比例）依然从 `tokens.ts` 直读，稿子不可能与代码漂移。

定格分镜当场抓到一处只有看图才发现的问题：**洇圈放大到 1.5× 时读起来是「外面又套了一个框」，不是「墨从印边洇出来」**（而且填充式低透明度光晕属于 §9.11 明令禁止的投影语汇），改为贴印边 1.22× 才对。

同时修掉稿子自身两处故障：CJK 回退字体把印面四字撑成 4 行、裁掉了「今」；`.calrow` 的百分比列宽在无固定宽度容器里塌陷。**稿子本身也要先核对，否则它就从复核工具变成误报源。**

### 9.14 第五轮：完整度印 / 释义列表基线 / JSX 排版即代码（2026-09-18）

主人验收第四轮后给了三条：**① 导入页点开就红屏**（`Text strings must be rendered within a <Text>`）；**② 多义项释义列表格式丑陋**；**③ 打卡印记再次被推翻**——「复用今日已毕的章，做成斑驳战损版 / 稍微斑驳残缺版 / 完美无瑕版来表示背的多少，而且现在这个小框有点小，放大空间是够的」。补充一句：四个字太大就简化成一个「背」或「毕」。

#### ① 红屏：JSX 的排版本身就是代码

`import.tsx` 标题行把两个兄弟节点写在**同一行**、中间隔了几个空格：

```tsx
<Text …>自 定 义 词 库</Text>        <View style={{ width: 48 }} />
```

JSX 会把行内空白当成**字符串子节点**，于是 `<View>` 的 children 里混进了一段裸文本 —— React Native 直接红屏。`tsc` 对此零告警，断言也只查语义不查排版，**它能穿过所有绿灯**。判据：**同一行写两个兄弟节点时，节点之间的空白不是「排版留白」，是「内容」。** 兄弟节点必须各占一行（已全库排查 `app/**/*.tsx`，仅此一处）。

#### ② 释义列表：两处错位叠加，而不是一处

主人说「丑陋」，拆开是两个独立的错，且互相放大：

1. **序号没有 `lineHeight`**：默认约 19，正文是 25 —— 序号的基线比正文首行**高**，从第一个词条起就不齐。
2. **义项间距只挂在正文上**（旧硬编码 6）：第 2 条起，正文带着间距下移了，序号没跟着走 —— 序号浮在自己正文的上方。

修法三件套，全部落在 `Definition.tsx`：序号带上正文的 `lineHeight`（共用同一条基线网格）；间距挂到**行**上（`styles.row` 的 `marginTop`，序号正文一起动）；`alignItems:'flex-start'`（默认 `stretch` 会把序号拉满整行高、文字在框里居中，正好抵消第 1 条的修法）。另有两项顺手判据：

- **前缀同号**：序号、词性（`n.`）、领域标签（`[经]`）统一取 `正文 × 0.79`（`TAG_RATIO`）。前缀是**索引不是内容**，比正文小一号才读得出主次；此前三处各写各的字号。
- **单义项不编号**：30,565 词里 9,932 个（32%）只有一条义项，孤零零一个「1」不提供任何信息。`listed = Boolean(numbered) && senses.length > 1`。
- 删掉死参数 `rule` / `center`（调用方传了、组件里永远走不到的分支）——死参数让下一次改动的人以为那里有逻辑。

> 复核用「源码直读对照稿 → 无头 Edge 截图 → 直接读图」（本机模型已能读图，逐像素定位只作为读不清时的备胎）。放大图里旧版「1」「2」明显浮在正文上方、新版序号与正文同基线，一眼可判。

#### ③ 印记第三案：浓度不靠墨量，靠**印面完整度**

§9.13③ 的「墨量分档」被主人推翻。新方向：**复用完成页「今日已毕」那枚章**，用印面的**完整度**表达当日的量——背得少 = 斑驳战损，背满 = 完美无瑕。这比墨量好在一处根本点：**墨量是印刷变量，完整度是叙事变量**。同一枚章，盖得越少越破损，讲的是「这一天你只背了几个词」的故事，与完成页那枚完美的印是同一件事的两个状态，日历和完成页由此接上了同一套语言。

落地时立了三条判据：

- **一处伤口，三个深度（同手法三量级，不是三种手法）**。初版给三档用了三种磨损手法（断框 + 洇点 + 蚀字），17 枚印排进日历读起来是「脏」，不是「旧」。收敛为**只有一种手法**：右下角纸色缺口（`bite`），三档只是缺口的量级（0 / 0.24 / 0.4）+ 战损档多一处蚀字的伤口与一个墨点。日历是**一版拓片**，手法必须统一，量级才读得出来。
- **出现最多的档位必须最经看**。日历里最常见的是背得少的日子（L1 战损档）——它再「战损」也必须保得住方形轮廓（只咬一角），否则整版日历的多数格子都是碎的，全部印章的辨识度跟着陪葬。
- **9dp 读不出来的分辨率不是分辨率**（§9.13③ 同一句判据的延伸）。印面放大到 **22dp**（320dp 屏上日历可用宽约 35dp 的上限），且**只放得下一个字**——四字「今日已毕」改为单字「**毕**」（主人给的备选之一），指向完成页那枚大印，语义不断。
- `sealWear(total, max)` 放令牌层：日历格与图例必须用同一条规则（§9.13③ 既有判据）。`Seal` 的 `ink` prop 改为 `wear`，`stampInk` / `StampInk` 一并删除不留旧名。

#### 断言改写（49 → 53）：同一方法论第二次生效
§9.13 立「被推翻的设计必须改写为它站岗的断言」，这一轮它立刻被用上：`印记尺寸唯一（浓度靠墨量）` 断言里写着 `stampInk` / `StampInk` 必须存在——它保护的正是被推翻的墨量方案。改写后判据反转：`sealWear` 存在、`stampInk|StampInk|stampSize` **不许复活**、印面完整度三档同手法（`SEAL_WEAR` 里 3 档 `bite=0` < 2 档 < 1 档、`right: 0, bottom: 0` 只出现一次）。新增四条：印记尺寸真的够大（≥18dp）、释义列表基线三件套（序号 `lineHeight` / 间距挂行 / `flex-start` / 前缀同号 / 单义项不编号）、释义组件无死参数。

### 9.15 第六轮：返回不露白（2026-09-18）

> 「单词页面和选择辞书页面等**侧边滑返回**的时候都还会出现白光，需要进一步排查是不是所有的类似行为都有问题，并整改设计动效。」

§9.6 修过一次「白光」（当时钉了三层底色），这次**又**出现，说明那次的分层漏了东西。所以这轮先做的不是改代码，是**把「转场」这个动作拆成一张层表**，逐层问「这一帧它在不在」。

#### ① 先普查：全应用只有三类转场

`presentation` / `Modal` / `MOTION.sheet` 在代码里零出现 → 没有模态与浮层。会「透」的地方只有三处：Stack 推/返、Tab 切换、启动页。范围可控，逐个审。

| 转场 | 屏幕内容底 | **容器层** | 原生根视图 | 判定 |
|---|---|---|---|---|
| Tab 切换 | `sceneStyle` ✓ | 布局根 View ✓（§9.6 补的） | 白 | 已修 |
| **Stack 推 / 返** | `contentStyle` ✓ | **✗ 缺** | 白 | **本次元凶** |
| 启动页 → App | `BootScreen` ✓ | ✗ 缺 | 白 | 首帧白 |

#### ② 为什么 `contentStyle` 挡不住返回的白光

`contentStyle` 钉的是**屏幕内容**这一层。而 Android 原生栈（`react-native-screens`）在压栈时会把上一屏的视图**摘掉**，返回时要**重新挂载** —— 那几帧里「屏幕内容」这个对象根本还不存在，透过去看到的是容器（`ScreenStack`，自身无底色）→ 再往下就是**原生根视图**（默认白）。

> **判据：「不露白」要按「哪一层在那一帧存在」分层钉，不是补一处就算完。**
> 一个只覆盖「内容」的底色，管不住「内容还没被创建」的那几帧。

§9.6 给 tabs 补的就是这一层（`(tabs)/_layout.tsx` 的 `<View flex:1 backgroundColor>`），**stack 这一侧一直没补**。所以同一个 bug 修了一半：tab 切换干净了，栈的返回还在闪。

#### ③ 第二处：`PageEnter` 把纸底也一起淡掉了

```tsx
<Animated.View style={[{ flex: 1 }, style, { opacity: v }]}>   // ← style 里有 backgroundColor
```

整屏（**含纸底**）在 240ms 里从透明淡到不透明 —— 这段时间屏幕是半透明的，底下同样是容器 / 窗口。这是「白光」的第二个来源，而且它最伤：它把**本该最先到位的东西**（纸）变成了最后到位的。

改为**拆两层**：底色提到外层、**不参与动画**，只有内容淡入。语义与完成页「先落印、后显字」同构 —— **底是既成事实，内容是正在发生的事**。

> **判据：背景不参与入场动画。** 任何「整屏一起淡」的写法，都在把「纸」变成一种会迟到的东西。

#### ④ 整改动效：同一个动作的两半必须同时长

卡片位移由原生栈给（默认时长与 `MOTION.enter 240` 不一致），内容淡入是我们写的 → 「卡片已到位、内容还在淡」。补 `animationDuration: MOTION.enter`，两者共用一条时间轴（§9.5 既有判据的直接应用）；「减弱动效」时归零（直接到位，不是变慢）。

#### ⑤ 四件套与取舍

| 层 | 修法 | 说明 |
|---|---|---|
| Stack 容器层 | `<View flex:1 backgroundColor={c.bg}>` 包住 `Stack` | 与 tabs 同法，theme-aware，兜住「内容还没挂上」的帧 |
| 屏幕内容 | `contentStyle` | 保留 |
| 纸底不淡入 | `PageEnter` 拆两层 | 纸先铺好，墨后落 |
| 原生根视图 | `app.json` → `android.backgroundColor` = 纸色 | ⚠️ **构建期常量，跟不了深浅模式**：暗色下那几帧是浅纸色而不是墨色。稳态由 JS 侧那层 theme-aware 的纸底负责，这一层只兜「JS 还没画出来」的瞬间（冷启动首帧） |

> 最后一层的取舍写在这里免得被当成完美方案：它能消灭冷启动白闪，代价是暗色模式下那几帧不是墨色。**已知并接受，因为那几帧短于一次眨眼，而白闪不是。**
> 另：`app.json` 是严格 JSON，**不许写注释**（本轮踩了一次，`JSON.parse` 直接失败，Expo 侧也可能读不了）—— 理由一律写进本文档。
> 刻意没动状态栏：`expo-status-bar` 在依赖里但全项目零使用，而 `backgroundColor` 在半透明/边到边模式下是否生效无法在本机验证 —— **不拿无法验证的改动冒充打磨**。

#### 断言（53 → 57）

新增四条，全部直读源码：`转场底色：卡片 + 场景 + **两个容器层**`（stack 容器层在列）、`纸底不参与淡入（PageEnter 拆两层）`（并禁止旧的「整屏一起淡」写法复活）、`原生根视图底色是纸`（读 `app.json` 与 `tokens.ts` 实比对，不写死色值）、`卡片位移与内容淡入同一时长`（`animationDuration` 必须走 `MOTION.enter`，禁止裸数字）。
