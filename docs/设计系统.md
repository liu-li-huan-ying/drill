## 0. 设计语言的由来

第一版原型做出来「没有辨识度」——靛蓝主色 + 16dp 圆角卡片 + 四色块评分按钮，本质是 Material 默认件的排列组合，换任何一家背单词 App 的 logo 都说得通。

问题在于**没有回答「这个 App 看起来应该像什么」**。市面上的共同形态是：无衬线字体、圆润卡片、插画或 emoji、高饱和渐变主色、游戏化打卡。单词在这些界面里只是**内容**，不是**主角**。

**「朱批」的回答是：让单词本身成为设计。**

三个记忆点：

1. **单词用衬线大字**（Iowan Old Style / Georgia / Noto Serif），UI 其余部分用无衬线。这是中英混排的经典做法，也是背单词 App 几乎没人做的。读起来像一页印刷品，而不是一张卡片。
2. **朱砂红 `#C0452F`** 作为唯一的强调色，只出现在极少数位置：主按钮、选中标记、进度条、「重来」档、词性标签。大面积留给纸白与墨黑。取自旧书上那支批注的笔。
3. **评分按钮顶部的横条长度 = 下次间隔**。重来 14dp、困难 26dp、良好 42dp、简单 66dp。不用读数字就能看出四个档位的量级差异——把抽象的「困难/良好」翻译成可见的长度。

## 2. 配色令牌

亮暗两套由**同一组令牌名**驱动，运行时跟随系统 `appearance`。

| 令牌 | 用途 | 亮（纸） | 暗（墨） |
|---|---|---|---|
| `--bg` | 页面底色 | `#F7F4ED` | `#131211` |
| `--sf` | 卡片面 | `#FDFCFA` | `#1B1A18` |
| `--pg` | 机身/分组底 | `#EFEBE3` | `#0D0C0B` |
| `--tx1` | 主文本（墨） | `#171512` | `#F0EBE2` |
| `--tx2` | 次要文本 | `#6E675E` | `#A69E93` |
| `--tx3` | 弱化文本 | `#A29A8E` | `#736C62` |
| `--bd` | hairline | `#E9E3D8` | `#2A2722` |
| `--bd2` | 描边 | `#DAD3C5` | `#494337` |
| `--ac` | 朱砂 | `#A8382A` | `#D0684F` |
| `--acsf` | 朱砂浅底 | `#F8EEEA` | `#2D201B` |

底色不是纯白而是**暖调纸白**（`#F7F4ED`，纸面 `#FDFCFA` 压在其上拉开层次），暗色不是纯黑而是**暖调墨黑**（`#131211`）——纯白/纯黑会让衬线字显得廉价。**朱砂取印泥红 `#A8382A`（亮）/ `#D0684F`（暗）而非亮橙红**——沉稳、有落笔的分量感（2026-09 定案，随 v3 原型）。

### 四档评分

| 档位 | 亮·底 / 字 | 暗·底 / 字 | 条长 |
|---|---|---|---|
| 重来 Again | `#F7EBE6` / `#C0452F` | `#2E211C` / `#E0705A` | 14dp |
| 困难 Hard | `#F2EEE5` / `#1B1917` | `#262320` / `#EDE8DE` | 26dp |
| 良好 Good | `#F5F3EC` / `#1B1917` | `#242720` / `#EDE8DE` | 42dp |
| 简单 Easy | `#EAEDE4` / `#1B1917` | `#212420` / `#EDE8DE` | 66dp |

只有「重来」用朱砂，其余三档靠底的冷暖微差 + 条长递进区分。不做四色高饱和色块。

> **令牌纪律（踩过坑）**：`body` 的文字色**必须走 `var(--tx1)`**，不得硬编码深色（如 `#1B1917`）。曾因 `body{color:#1B1917}` 硬编码，而 `body.ink` 只定义变量没覆盖它，导致**暗色模式下所有未显式设色的文字（刻度环数字、数据卡数值、完成屏标题、浮层标题、详情词面）继承成黑字、在墨黑底上全瞎**。修复：把 `body{color:#1B1917}` 改为 `body{color:var(--tx1)}` 并给 `.app` 兜底。同理——任何新文本元素要么显式 `var(--tx*)`，要么依赖继承的 `var(--tx1)`，绝不写死颜色。

## 3. 字体

两套字族分工明确：

- **衬线 `--serif`**：`Iowan Old Style, Palatino Linotype, Georgia, Times New Roman, Noto Serif, Source Serif 4, serif`
  用于：单词、页面标题、例句（斜体）、释义编号、统计数字
- **无衬线**：系统默认
  用于：释义中文、列表、按钮、标签、设置项
- **等宽**：`SF Mono, Consolas, monospace`
  用于：音标（配合 +0.8px 字距，词典感）

| 级别 | 字号 | 用途 |
|---|---|---|
| 42 sp 衬线 | 复习/新词卡单词 |
| 36 sp 衬线 | 测试词 |
| 33 sp 衬线 | 详情页单词 |
| 27 sp 衬线 | 卡背面单词、统计数字 |
| 25 sp 衬线 | 页面标题 |
| 16.5 sp 无衬线 | 中文释义 |
| 14 sp 衬线斜体 | 英文例句 |
| 13 sp 等宽 | 音标 |
| 10.5 sp 无衬线 | 小标签，uppercase + 1.1px 字距 |

### 字重（2026-09-18 修正，推翻旧结论）

> 旧结论写的是「中文层级不靠字重（中文无 light 档、bold 小字号糊），靠字号 + 字距 + 颜色」——**这是错的**。实测反馈：标签 / 按钮 / 小字用 Regular(400)，在中文屏显下**细弱无力、显廉价**；而靠拉宽字距假装层级，只会更散。**这两个毛病叠在一起，就是「实习生感」的来源。**

| 角色 | 字重 | 说明 |
|---|---|---|
| 正文长文（释义 / 例句 / 浮层说明） | **400** | 长文才用 Regular，加粗反而糊 |
| 标签 / 按钮 / 标题 / 数字 / tab 标签 | **600** | 10–24px 区间一律 600；PingFang SC Semibold 在小字号依然清晰，是「有力量」的直接来源 |
| 列表项标题 / 次要数值 / tab 未选 | **500** | 中间档，不抢主体也不虚 |
| tab 选中 | **600** | 与未选拉开 |

判据一句话：**「这行字要不要压住周围？」**——要，就 600；只是陪衬，就 400。**层级靠字重，不靠无意义的宽字距。**

## 4. 细节纪律

这几条是「有设计感」和「没设计感」的分界线，实现时必须遵守：

- **分割线一律 hairline**——1px，颜色用 `--bd` 而不是 `--bd2`。粗线是廉价的头号来源。
- **所有数字 `font-variant-numeric: tabular-nums`**——包括进度、词数、间隔、统计。数字跳动会毁掉排版。
- **小标签分两类**：拉丁文 `uppercase` 用宽字距（+1.1px，报纸法则）；**中文全角标签不加宽字距**——10px 级「章印式」小标签可留 1.6–2.2px 作装饰，**11px 以上的中文标签一律 0–1px**（给中文加 1.6px 以上字距是拉丁全大写惯例的误用，只会显松散）。
- **标记不用圆点也不用纯色块**——底部栏选中态用「**朱笔横痕**」（有起收笔的 30×4 笔触，切换时滑动），状态点用内描边小印（`inset` 描边）。圆点太软，纯色块太廉价。
- **图标 stroke-width 1.5**，不填充，tab 图标 22×22。
- **例句用衬线斜体**，关键词不用加粗，用 `--tx1` 提亮或朱砂下划线。
- **不做渐变、不做长阴影**。卡片阴影极轻或只用 1px 描边。

## 5. 关键交互决策

### 5.1 新词与复习走两条不同的路（v2 新增）

v1 原型只有一张翻转卡 + 四档评分，这是个**语义缺陷**：一个从没见过的词，让用户在「重来 / 困难 / 良好 / 简单」里选，FSRS 的首次评分语义是崩的——Again 表示「忘了」，可你根本没记过。

拆成两张卡：

| | 新词卡 | 复习卡 |
|---|---|---|
| 顶部标签 | 首 次 接 触 | 复习 12 / 47 |
| 底部按钮 | 不认识 / 认识（**认知判断**） | 重来 / 困难 / 良好 / 简单（**记忆评分**） |
| FSRS | 首次评分为 Good 入队，具体 due 由首评决定 | 正常四档调度 |

### 5.2 卡正面只有「单词 + 音标」

不显示释义、不显示例句。正面信息越多，用户越容易在回忆之前被动接收，回忆强度下降。音标是发音线索不算答案，保留。

### 5.3 评分按钮显示下次间隔（长度 + 数字双编码）

沿用 Anki 已验证的做法，并加一层视觉编码：条长表达量级，数字表达精确值。

### 5.4 「想不起来按重来」

FSRS 里 Hard 的语义是「想起来了但吃力」，Again 才是「没想起来」。新手普遍误用 Hard，导致调度器把没记住的词排到远期。评分区上方常驻提示行。

### 5.5 详情页纵向单列，不做内分页

不背单词用了「释义/例句/助记」分页 tab，观感整洁但查一个词要点三次。本设计单列滚动，一屏看全。排版按词典条目：编号 + 词性 small-caps + 释义。

### 5.6 熟词校准：不是一个功能入口，拆成两处

原本设计是首页底部一个「词汇量测试」入口。斟酌后的判断是：**它本质是冷启动校准，不是学习功能**，所以不管放首页还是设置页都别扭——

- 放首页：「未测」这个标签会永久挂着，变成噪音和心理负担
- 放首次启动强制做：60 题 × 3 秒 = 3 分钟，对一个还没建立信任的 App 是流失点
- 藏设置页：用户永远不会点，等于没有

拆成两件事：

| | 触发时机 | 形态 |
|---|---|---|
| **首次校准** | 未校准状态下点「开始学习」 | 先走 20 题（约 30 秒，右上角可跳过），做完直接接今日新词。不是一个独立关卡，是「开始学习」的第一段 |
| **熟词校准** | 随时，可反复 | 首页底部常驻入口，显示「已校准 N 词」的中性状态；设置页也可进 |

配套第三条：**「标为已掌握」是常驻动作，不是集中测试**。真正高频的场景不是第一次校准，而是「背 GRE 时遇到一个早就会的四级词」。这个入口分布在卡片背面、单词详情页、搜索结果、词库列表长按——随时可用。

因此首页底部不再是「未测」这种负罪标签，而是一个中性的、可反复使用的工具入口。

### 5.7 不做游戏化

无连续打卡徽章、无排行榜、无鼓励弹窗、无成就。统计页只给数据。

## 6. 首页：保留（v2.1 定案）

首页的价值是"做数量上的心理准备"，直接甩进复习队列少一个缓冲。v2.1 的两处增强：

- **进度环改为 20 格刻度环**——一格 = 今日一个配额，已完成填朱砂、未完成用 `--bd`。连续圆环只能表达百分比，刻度环能**数**，也更接近仪表盘的手感。
- **主按钮下方加预计时长**（「预计 18 分钟 · 含 20 题熟词校准」）——把抽象的"20 个词"翻译成时间承诺，这是降低放弃率最有效的一行字。

### 卡片翻转动效

原型内可点击体验。实现要点：容器 `transform: perspective(1400px) rotateY(180deg)`，两面 `position:absolute; inset:0; backface-visibility:hidden`，背面初始 `rotateY(180deg)`。时长 500ms，曲线 `cubic-bezier(.32,.72,.28,1)`。评分按钮需 `stopPropagation`，否则点评分会连带翻回正面。

## 8. 无障碍

- 正文对比度 ≥ 4.5:1（WCAG AA），大字 ≥ 3:1
- 不靠颜色单独传达状态：四档评分同时有颜色 + 条长 + 文字
- 支持系统字号缩放，卡片内容区可滚动

## 9. 设计体系 v3 · 原理与尺度（2026-09 新增）

> 背景：审查发现圆角在代码中出现 **10 种取值**（文档规定 6/8/10，`12` 出现 5 次超上限）、按钮高度 **8 种**、动效**零实现**（原型有 500ms 翻转，App 里是 `useState` 瞬切）。结论：缺的不是古风元素，是尺度与动效两根支柱。

### 9.1 三条原理（可判定）

| 原理 | 含义 | 判据 |
|---|---|---|
| **臣服** | 单词是唯一主角，界面臣服于它 | 任何界面元素若比单词更抢眼，不通过 |
| **痕迹** | 朱砂只标记人的痕迹（批注、标记、评分） | 问「这是人留下的还是机器生成的」——机器生成的一律中性色 |
| **量度** | 量级必须有物理编码，不能只有数字 | 凡表示「多少 / 多久」的信息，必须有长度或面积编码 |

底线：**宽容 + 可达**（评分可撤销、主行动在下半屏单手可达区）——美观不得挤掉这两条。

### 9.2 尺度系统（`src/theme/tokens.ts`，唯一取值来源）

| 组 | 档位 |
|---|---|
| 圆角 `RADIUS` | mark 1 / bar 2 / chip 6 / ctrl 10 / card 12 / pill 999（圆形一律 pill，不再随直径手算） |
| 间距 `SPACE` | 4dp 网格：1 / 4 / 8 / 12 / 16 / 20（页边距）/ 24 / 32 / 40 / 48（触摸目标） |
| 控件高 `CONTROL` | sm 38 / md 44 / lg 50 / xl 54（原 8 种归并为 4 档） |
| 动效 `MOTION` | press 120 / fade 200 / flip 500 / sheet 280（ms） |
| 字重 `WEIGHT` | regular 400（正文长文）/ medium 500（列表项、次要值、tab 未选）/ semibold 600（标签、按钮、标题、数字、tab 选中）——见 §3「字重」 |
| 层级 `LAYER` | flat 0 / card 1（1px 描边）/ overlay 3（浮层） |

动效曲线规范：**纸的物理性——慢而稳、有阻尼、无回弹**（翻转 500ms `cubic-bezier(.32,.72,.28,1)`）。不做 spring，纸不会弹。

### 9.3 古风版式（v3 原型「版式」开关可对比）

- **版框**：内容卡加 `1px --bd2` 描边——从「悬浮的白块」变「纸上的一页」。只给内容卡加，列表项加框会变表格。
- **天头 > 地脚**：卡内边距上 34 / 下 18（古书版式上留白大于下）。只用于固定高度卡片，滚动容器保持均匀。
- **界行**：释义区左侧 `1px --bd` 竖线（竹片缝）。
- **朱文印**：标记类元素（计数点、状态点）用「内描边印章」而非纯色块——`inset 0 0 0 1px` 内边，从色块变印章。
- **明暗对偶**：亮 = 竹简·宣纸（`--bd2 #DAD3C5` 压痕、朱砂沉 `#A8382A`）；暗 = 碑刻·拓片（`--bd2 #494337` 拓痕白边、朱砂提亮 `#D0684F` 如印泥）。共用同一组令牌名，切换的是意象不是结构。

### 9.4 导航与过渡（v3 原型 · 底部栏重做）

**为什么不许用小红点**：7px 圆点是状态指示（未读），不是导航语言；5 格里各挂一个，等于把导航降格成开关，廉价且糊弄。选中态必须能被「一眼读懂 + 一眼看出移动过」。

| 元素 | 规格 | 理由 |
|---|---|---|
| 朱痕指示器 | 30×4 SVG 笔触（有起收笔，`stroke-linecap:round`），切换时 `translate3d` 滑动 380ms，与页面同曲线 | 「你在这里」是人的痕迹 → 用朱砂（合**痕迹**原理）；会滑动才看得出页面关系 |
| 图标 | 22px 线性 `stroke-width:1.5`、`currentColor`；选中转 `--ac` + `translateY(-1px) scale(1.06)` | 纯文字导航没有图形锚点，识别慢 |
| 标签 | 选中字距 `0.8 → 1.1`、色 `--tx3 → --tx1`（中文全角字，字距过宽是拉丁全大写报纸惯例的误用；只给 10px 级「章印式」小标签留 1.6–2.2px 宽字距） | 选中三重编码（色 + 字距 + 位移），不依赖单一颜色 |
| 栏高 | 内容 62 + 上 8 + 下 10 = 80（含安全区），单格触摸区 ≥ 62×栏宽/5 | 原 64px 内容区偏挤 |
| 栏上渐隐 | tabbar 顶部 22px 向 `--bg` 的渐变遮罩 | 内容不再被 1px 硬边切断 |

**页面过渡必须有方向感**：按故事流程 `home → learn → done → word → stats → set` 判前后，前进从右 18px 淡入、后退从左 18px（`340ms cubic-bezier(.32,.72,.28,1)`）。单向 fade 表达不了「进去了 / 退出来了」。
**底部栏自动跟随**：任何 `go(screen)` 都按 `data-t` 反查对应 tab 高亮并滑动朱痕；`done`（完成屏）无 tab，保持「学习」高亮——它属于学习流程的收尾，不该让导航跳走。

### 9.5 趋势对齐（iOS 26 Liquid Glass / Material 3 Expressive，2025–2026）
> 2026-09 核查两家最新设计语言后，对其可融合朱批的部分做了取舍。原则：**取其神不取其形**——形态语言（玻璃、大圆角、弹簧）会破坏纸/墨调性，但架构与纪律（分层、同心、触摸目标、hero、垂直韵律）值得吸收。

**吸收的（落到原型）**
- **控制层 / 内容层分离（苹果）**：底部栏、评分条是「控制层」，浮于内容之上；内容（单词）永远是主角（合**臣服**原理）。
- **同心圆角（苹果 concentricity）**：嵌套圆角跟随周围几何，内半径 < 外半径。
- **触摸目标 ≥ 48dp**（iOS 44 / Android 48，取严）：所有可点元素 ≥ 48。
- **内容分组容器（谷歌 containment）**：相关信息进同一容器，靠留白与最亮表面突出重点。
- **hero moment（谷歌）**：全产品只 1 个高潮——完成屏朱印「盖下」，短暂、有分量、不重复。
- **垂直韵律 / 字号阶梯（两家都强调 typography rhythm）**：分层靠**字号 + 颜色**，不靠无意义的宽字距；中文全角字不该照搬拉丁全大写的 2px 字距。

**没吸收的（会毁调性）**
- Liquid Glass 透明/折射材质——与纸不透明、墨沉的物质感冲突。
- 动态多色强调——破坏「朱砂只标人的痕迹」的单色体系。
- 盲目放大圆角——古书不该有塑料感，卡片圆角 12 封顶。
- 弹簧回弹——纸不会弹，只用阻尼 settle（无过冲）。

### 9.6 实现纪律（原型已落地，App 落地时照此）
- **触摸目标**：iconbtn 48 / soundbtn 48 / undo 钮 48 / tab 62 / 列表项 58（dp）。
- **同心圆角**：card/stat/grid3/fce = 12；按钮/评分 = 10；chip = 6；switch = 24 圆；嵌套内 < 外。
- **hero**：完成屏 `.sealbig` 落印（`stamp` .52s 阻尼，scale .72 + 旋 -4°→0，无回弹）；`grid3` 三格错峰 `rise`。
- **按压反馈**：按钮 scale .985/.96、tab scale .96，无生硬瞬切。
- **暗色令牌纪律**：见 §2 令牌纪律——文字色一律 `var(--tx1)`，绝不硬编码深色。

### 9.7 主人验收反馈修正（2026-09-18）

- **字重太细 = 廉价**：「很多字体都太细，没力量、简陋」。修正见 §3「字重」——标签/按钮/标题/数字全局提到 600，正文留 400。**旧结论「中文层级不靠字重」作废。**
- **「易忘」标签太简陋**：裸竖排两字无装饰 = 像随手贴的标签。改为**白文朱印**——30×46 朱底纸字小方章（宋体、600、方角），有古书批点的分量感。
- **打卡记录看不懂**：「我没看懂你这些格子代表什么」。35 格无标注热力图 → **月度日历**：星期表头（日一二三四五六）+ 每日日期数字 + 朱砂明度四档 + 脚注「9 月 · 打卡 15 天 · 连续 12 天」。**判据：可视化的每一格必须自明——没有表头 / 日期 / 刻度的格子等于谜语。** 格子收窄居中（max-width 252），不做无意义的大空格。
- **删除冗余**：统计 hero 右侧的周环（与副文「本周 4 / 7」重复）已删——**功能删除要彻底：样式 + HTML + 函数 + 调用一起删，不留死代码**。
