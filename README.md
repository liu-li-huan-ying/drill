# 背呗 (drill)

一个完全离线、零订阅的背单词 App。React Native + Expo 构建，自己掌控数据，不向任何付费墙低头。

## 为什么有这个项目

受够了背单词软件把「单词上限」「优质词库」「例句与助记」做成付费点。这些能力在开源世界里基本都是免费的：

- 调度算法有 **FSRS**（开源，比 SM-2 少 20-30% 复习量达到同等留存率）
- 词库有 **ECDICT**（MIT 协议，150 万词条，带考纲标注与词频）
- 例句有 **Tatoeba**（CC BY，英中平行句对可离线打包）

所以——自己写一个。

## 核心设计

- **总库 + 标签模型**：3 万词全局词库（含 GRE 全覆盖），「词库」只是单词上的标签。同一个词无论属于几个词库，全局只有一条复习记录，不会重复背。
- **纯离线**：App 运行时完全不联网、不调 LLM。AI 只出现在离线数据准备阶段（补例句缺口）。
- **数据归你**：不做云同步，进度可导出为本地 JSON 备份，换设备导入接续。
- **FSRS 调度**：四档评分（Again / Hard / Good / Easy），完整发挥 FSRS 精度。

## 技术栈

| 层 | 选型 |
|---|---|
| 框架 | Expo SDK 57（React Native 0.86 + React 19.2） |
| 语言 | TypeScript strict |
| 路由 | Expo Router（文件路由） |
| 本地库 | expo-sqlite（原生 SQL） |
| 调度算法 | ts-fsrs |
| 发音 | expo-speech（系统 TTS，零成本离线） |
| 样式 | StyleSheet + 统一 theme（见 [docs/设计系统.md](docs/设计系统.md)） |

> - **设计体系 v3.5 · 多机型弹性布局 + 转场打磨**：主人反馈「适配多种机型不够好，长宽比各不相同，该用弹性空间布局」+「切换动效没做或没打磨，切换很不舒服」。

> - **设计体系 v3.6 · 转场设计（本轮）**：主人反馈「页面切换会闪一道白光，而且你得设计页面切换的动效啊，很生硬很劣质，要在细节上保持品牌调性」。
>   - **白光不是动效问题，是「透光」**——三层底色没钉住。`Stack.contentStyle`（原生栈卡片默认白，页面 JS 内容渲染前先露出它）、`Tabs.sceneStyle`（场景容器默认透明，交叉淡入时透过去看到下层）、tabs 布局根 View（同样透明）三处全部钉成 `c.bg`。判据：**任何会做淡入/交叉的容器都必须自己有底色** —— 淡入本质是把不透明度从 0 拉到 1，中间那段观众看到的是下一层。
>   - **同级切换是语义问题，不是手感问题**：内置 `shift` 预设位移 **±50dp**，那是「整页滑过去」＝**走进下一页**的量；用在同一层级的两个 tab 之间，语义不对，观感就是被推来推去的硬纸板。改为自定义 `sceneStyleInterpolator`「**纸页轻推**」：方向感知 **±14dp** + 交叉淡入（原型页间 18dp，tab 更轻），曲线换朱批主曲线（减速），时长仍与朱痕同值 300ms。**判据：位移量表达层级关系 —— 同级 ≤16dp，跨级才用整屏。**
>   - **纵深屏：系统管卡片，我们管内容**。卡片推进是原生栈给的（改不了），内容是唯一能设计的那一层 → 新增 `PageEnter`：内容比卡片晚半拍「显影落定」（透明度 `MOTION.enter = 240ms`）。**只做透明度不做位移** —— 系统横向推 + 我们竖向浮 = 斜向运动，正是「业余感」的来源。8 个栈屏根容器全部接入；**tab 屏不用**（场景自己已有交叉淡入，套两层会发飘）。
>   - **曲线收敛成两条（全项目没有第三条）**：`EASE = [0.32,0.72,0.28,1]` 主曲线（起步快、收尾长、无过冲——纸不会弹）、`EASE_SETTLE = [0.22,1,0.36,1]` 落印曲线（印章只有一次，要「啪」地定住）。以贝塞尔控制点导出，保留令牌文件零依赖；**各处手写 `Easing.bezier(数字)` 已被断言禁止**（动效的廉价感八成来自「每条动效各用一个 ease」）。
>   - **减弱动效**：新增 `useReducedMotion()`，动效**不是变慢而是直接到位**（变慢对前庭敏感用户更难受）。覆盖页面入场、tab 位移（只留交叉淡入）、朱痕滑动、卡片 3D 翻转、完成屏落印。
>   - **刻意没动的**：`fullScreenGestureEnabled` / `animationMatchesGesture` 只在 iOS 生效、本机无法验证，且会改变 iOS 上 push 的默认动画（官方文档明说默认 iOS 手势动画不可复现）。iOS 边缘返回本来就是跟手的 —— **不拿无法验证的改动冒充打磨**。
>   - **验证**：24 条断言全绿（新增「三层底色不露白 / 自定义插值器 / 曲线单一来源 / PageEnter + reduce-motion」4 条）+ `tsc --noEmit` 零错误 + `expo export` 打包通过（3MB hbc）。

> - **设计体系 v3.7 · 第二轮验收修正（本轮）**：主人反馈「白色模式下统计和设置切换时各个框的阴影会显示很久」「词库这些为什么都是灰色的，死气沉沉」「点进去有个『只背这一纲』超级长」。
>   - **阴影的毛病不是「重」，是「不消隐」**：投影只加在亮色的 `Card` / `ReviewCard` 上，而 **Android 的 `elevation` 是平台阴影**——RN 只映射 `shadowColor`（API 28+），`shadowOpacity / shadowRadius / shadowOffset` **在安卓上被忽略**，所以设计稿写的「5% 极轻阴影」在真机上根本不存在，落地的是平台那层重得多的黑边；更要命的是它**不随祖先 `opacity` 的交叉淡入消隐**（投影由平台单独绘制），tab 切换时旧屏卡片的投影会滞留在新屏上——这正是「阴影显示很久」的机制。**做法：删掉 `SHADOW` / `LAYER` 两个令牌**，抬升一律用「面比底亮一档（`sf` 压 `bg`）+ 1px 描边」，与 §9.3 版框同源，顺带消掉「iOS 柔和 / 安卓滞后黑边」的两端不一致。
>   - **「中性」不等于「看不见」**：词库行的条色原取 `bd2`、而轨道是 `pg`——实测对比度只有 **1.25:1**，8 行「量度」画了等于没画，整屏只剩浅灰。改为走**墨阶**：名称 `tx1`·500 / 词数 `tx2`·600 衬线 / 条填充 `tx2`（选中 `ac`）/ 方印描边 `tx2`；轨道回归原型取值 `bd2`——量度的「满额」要有容器才读得出占比。标记由**实心灰圆点**改为 1px **内描边小方印**（朱文印；§9.3 明令标记类元素不用纯色块），选中态才落朱砂实底，自定义导入的词表用虚线方框区分（原型 06 屏写法）。朱砂仍然只标「你正在背的这一本」——**中性靠墨阶表达，不靠彩色**。

> - **设计体系 v3.9 · 第四轮：落印与印记（本轮）**：主人验收第三轮后提出四条否定与一条要求。四条否定里有两条是**真 bug**、一条是**设计方向被推翻**、一条是**新增要求**，而它们指向同一个根因：**把「设计意图」写进了代码，却没有人验证意图是否真的抵达了屏幕**。
>   - **① 词库的「在背」朱砂标记看不到**（主人：「预览里显示选择辞书会用红色标记，但实际并没有看到这个效果」）。根因不是样式，是 **过期快照**：`library.tsx` 第 16–19 行在**渲染期**一次性求值 `getTags()` / `getWordCount()` / `getStudyScope().tagId` —— 而 tab 屏切走不卸载、切回不重挂载，于是这三个值永远停在首次进入那一刻；学习范围在词单页改过之后，回到词库看标记**永远不会出现**。改成 `useState` 初值 + `useFocusEffect` 重读（与 `index.tsx` / `stats.tsx` 同一模式）。**这个坑本仓库踩过第二次，所以它现在是一条断言**：三个读库的 tab 屏，查询函数只允许出现在 `useState` 初值或 `useFocusEffect` 回调里，不许出现 `const x = getXxx()` 这种渲染期直读。
>   - **② 完成页盖章动效「根本和描述完全不符，看起来只是屏幕抖动了一下」**。根因有两条，且都能算出来：`stamp` 0→1 交给**一条** `EASE_SETTLE` 急收曲线跑满 520ms，再用插值停点 `[0, .72, .88, 1]` 表达「落 / 触纸 / 回弹 / 定住」—— 而 `cubic-bezier(.22,1,.36,1)` **前 20% 的时间就走完约 80% 路程**，于是停点 `.72` 落在约第 15ms（≈1 帧）；更要命的是旧 `sealStyle` 里**根本没有 `translateY`**，只有 `scale` 与 `rotate`：于是「章掉下来」退化成「章在原地变大」，屏幕上唯一在动的就是那 1.6dp 的纸面微震。**结论写进体系：一条曲线只能塑造一段动作的形状，不能承载一条时间轴。** 改为**三段独立时长**——落 `sealFall 200`（走新曲线 `EASE_FALL`，起步慢收尾快 = 加速，因为下落是**重力**不是「被推了一下」，这与主曲线方向恰好相反）/ 压 `sealPress 90`（触纸瞬间比例过冲到 1.09，印泥被压开）/ 收 `sealSettle 170`（回弹到 0.985 再定住），并补上真正的**下落位移**（`translateY −30 → 0` + `scale .88 → 1.09` + `rotate −6° → 0`）；微震与新增的**朱墨洇开**（贴印边 1.22×、320ms）都是**落印的后果**，起点统一为 `Animated.delay(MOTION.sealFall)`；标题与三格数据**在印落定之后才显影**（`delay = sealFall + sealPress`）——次序就是语义：先落印再显字 = 批注，字先铺好、印后盖上 = 表单盖章。`SEAL_IMPACT` 与 `STOPS` 一并删除（不留旧名字，否则下一个改这屏的人会顺着它把插值停点写回来）。
>   - **③ 打卡印记的「尺寸递增」被否决**（主人：「大小绝对是要一样大的，不然大大小小放一起很不好看」）。这句话背后是一条比「好不好看」更硬的编码原则：**重复出现、且必须并排比较的元素，不能用尺寸编码差异**——日历里 30 格是一排读数，尺寸一多样，眼睛比的是「哪个更大」而不是「哪天的墨更重」；何况相邻两档只差 1.6dp，比大小本身也不成立。改为**同尺寸（9dp）+ 墨量分档**：细边朱文（1dp 边，只有轮廓）→ 粗边朱文（1.9dp）→ 满墨白文（印面全朱 + 纸色内框，这是白文印真实的结构：朱是底、「字」是纸）。只分三档，因为 9dp 印面上「细/中/粗」的边界已接近可辨极限——**读不出来的分辨率不是分辨率，是噪声**。分档规则放进令牌层（`stampInk(total, max)`）而不是屏幕里：日历格与图例必须用同一条规则，否则图例就会和日历说不同的话。`Seal` 原子随之从 `variant:'solid'|'text'` 改为 `ink: 1|2|3` + `paper`（白文内框要取印下面那张纸的颜色，永远取 `c.bg` 会在卡面上暗一档、读成空心框）。
>   - **④ 「很多动效可以结合朱批和盖章这两个行为去延伸拓展」**。据此立下**动效语汇**：判据只有一句——**这个动效是在「写」还是在「盖」？** 写 = 人的动作（有过程、有方向、留锋、可撤销）→ 慢、展开；盖 = 确认（瞬时、块、已成事实）→ 快、压印。落地四处：详情页**朱笔横痕由左向右划出**（`width 0 → 168`，`stroke 260`，走主曲线快起慢收 = **收笔减速就是「留锋」**在时间上的表达；`width` 是布局属性故 `useNativeDriver:false`）；词库「在背」与日历印记用**钤下**（`sealTamp 150`，比例 1.24/1.3 压到 1 + 淡入，起始比例**比 1 大**——印落在纸上的一瞬比静止时大）；日历进入时**错峰钤印**（只给打了卡的日子排拍子、封顶 12 拍 ≈190ms，聚焦时重播）。`SealMark`/`Seal` 的既有语汇（朱文 / 白文）与这套「写 / 盖」是同源的：**朱文印只留轮廓 = 线 = 写，白文印满墨 = 块 = 盖**。

## 数据管线（离线跑一次）

词库是离线预处理产物，不进运行时。`assets/db/dictionary.db` 即随包词库（全量 30,565 词 + 例句），App 首次启动（或本地版本低于 `EXPECTED_DB_VERSION`）将其拷贝到用户目录后直接在其上写进度。重跑流程：

```bash
bash tools/fetch_ecdict.sh       # 下载 ECDICT 主词典（MIT）到 tools/cache/（不进版本库）
python3 tools/build_dict.py      # 筛选高频词 + 考纲标签，构建 assets/db/dictionary.db（user_version=2，M3）
python3 tools/build_examples.py  # 拉取 Tatoeba 英/中句 + links，构建 examples 表（user_version=4，M3.2）
```

`dictionary.db` 一次建好全部表——`words`/`tags`/`word_tags`/`examples` 为只读词库，`cards` 等用户表留空——App 首次启动将其拷贝到用户目录后直接在其上写进度，可跨表 JOIN，无需运行时再建表。`examples` 表由 `build_examples.py` 在 Tatoeba 周更导出上离线构建（`word_id, sentence_en, sentence_zh, ord`）：词→句通过词典词集合命中、句间翻译经 `links` 配对，纯字符串处理、可重跑；缺 links/cmn 时退化为纯英文例句。

## 依赖说明（重要，别踩坑）

本项目**必须用 `npm install --legacy-peer-deps`**：锁文件里 `react@19.2.3` 与 `react-dom@19.2.8` 版本不匹配（历史遗留），不带该 flag 会 `ERESOLVE` 直接中止安装。

但 `--legacy-peer-deps` 会**完全跳过 peerDependencies**——凡是只靠 peer 关系装上的包，npm 会当成「多余」清掉。`expo-router` 的原生必需依赖正是这种 peer：

- `react-native-safe-area-context`、`react-native-screens`、`expo-linking`、`expo-constants`

**规则：这些包必须在 `package.json` 里显式声明**（本项目已加）。否则一次 `npm install` 就会把它们剪掉，Metro 打包立刻报 `Unable to resolve "react-native-safe-area-context"`。

改完依赖后**务必验证三件事**再收工：

```bash
npm ls react-native-safe-area-context react-native-screens   # 1. 包在树上、版本对
npx tsc --noEmit                                             # 2. 类型零错误
npx expo export --platform android                            # 3. Metro 真打包能过
```
